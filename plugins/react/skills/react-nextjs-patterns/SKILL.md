# Next.js App Router Patterns

> Load `Use skill: stack-detect` first to determine the project stack. For state/store choices defer to `react-state-patterns`; for form/validation schemas to `frontend-form-handling`; for client data-fetching boundaries to `react-data-fetching`. Guard mechanics (placement, redirect flow, a missing re-check at the page or data layer) are owned here; session/token validity and auth-logic review belong to `task-react-review-security`.

## When to Use

- Designing or reviewing a Next.js 16 App Router service: route structure, layouts, loading/error UI, parallel and intercepting routes, `proxy.ts`, route guards
- Splitting work between Server Components, client islands, Server Actions, and Route Handlers
- Configuring caching (Cache Components or the previous model), invalidation, streaming, metadata, and `next/image`

Out of scope: Pages Router maintenance, generic React state, framework-neutral SEO. The Pages -> App migration is in scope.

The one fork in this skill is observable: `cacheComponents: true` set in `next.config` (Cache Components) or not (the previous caching model). Read it before prescribing any caching or segment-config form.

## Rules

- Server Components are the default. Add `"use client"` only for hooks, event handlers, or browser APIs - and push the boundary as far down the tree as possible. Layouts stay Server Components unless interactivity is required; `error.tsx` is always a Client Component.
- Server-only modules (DB clients, secrets, server SDKs) import `import "server-only"`. Never import them transitively into a client component.
- `params`, `searchParams`, `cookies()`, `headers()` and `draftMode()` are async-only: `await` them in Server Components; a Client Component unwraps the `params` / `searchParams` props with `use()` (`cookies()`, `headers()`, `draftMode()` are server-only). Type pages, layouts and Route Handlers with the global `PageProps<'/route'>`, `LayoutProps<'/route'>` and `RouteContext<'/route'>` helpers (generated by `next dev`, `next build` or `next typegen`; no import). Validate every dynamic param before use - it is untrusted input.
- Server Actions are public HTTP endpoints: authorize the caller, validate every input with a schema, then invalidate. Choose Server Action for first-party form/mutation flows; choose Route Handler only when you need a stable URL, non-form clients, webhooks, or non-JSON responses.
- Cache by intent. With Cache Components: data is dynamic by default; cache with `"use cache"` + `cacheLife` + `cacheTag`, wrap uncached or runtime reads in `<Suspense>`, and write no `dynamic` / `revalidate` / `fetchCache` / `dynamicParams` segment export. Without it: `fetch` is uncached by default; opt in with `next: { revalidate, tags }` or `unstable_cache`. In both, `await connection()` marks a read as per-request.
- Invalidate with the call whose semantics you need: `updateTag(tag)` in a Server Action that must show the user their own write, `revalidateTag(tag, "max")` for stale-while-revalidate, `revalidateTag(tag, { expire: 0 })` from a Route Handler or webhook needing immediate expiry, `refresh()` in a Server Action to re-render the client router after a write that touches no tag (it revalidates nothing). Never the one-argument `revalidateTag(tag)`, and never swap it for `"max"` by rename - that turns immediate expiry into stale-while-revalidate.
- `proxy.ts` (`export function proxy`) is an optimistic gate, not the authorization boundary: it redirects the obviously signed-out cheaply, and the page, action or data layer re-checks the session before returning anything. Keep it allocation-light (no DB or network calls, no heavy parsing - verifying a signed session cookie is fine), free of state or globals shared with render code, and scope `config.matcher` to the prefixes it gates. A layout check is not per-route either: a layout does not re-render on navigation within its own subtree.
- Every segment that can fail has an error boundary; every segment that fetches has a loading UI. Layouts do not re-fetch data the parent provides.
- Metadata via the Metadata API (`metadata` export or `generateMetadata`). No manual `<head>` writes.
- All images use `next/image` with explicit `width`/`height` (or static import); mark the LCP image `loading="eager"` (optionally plus `fetchPriority="high"`), or `preload` alone when one image is the LCP at every viewport - never `fetchPriority` alone, which still renders `loading="lazy"`.
- Navigate with `<Link>`; `router.push` only for post-mutation redirects; never `window.location` for in-app movement. Follow the file conventions - no hand-rolled router on top of them.

## Patterns

### App Router Conventions

```
app/
  layout.tsx              # Root layout (persists across all routes)
  page.tsx loading.tsx error.tsx not-found.tsx
  (auth)/login/page.tsx   # Route group - no URL segment
  dashboard/
    layout.tsx            # Persists across /dashboard/*
    page.tsx loading.tsx error.tsx
    [teamId]/page.tsx     # Dynamic segment -> (await props.params).teamId
    photo/[id]/page.tsx   # Real page - hard loads, refresh, shared links
    @modal/default.tsx    # Slot fallback (returns null) - required
    @modal/(.)photo/[id]/page.tsx  # Interceptor - soft navigation only
  api/users/route.ts      # Route Handler
proxy.ts                  # Beside app/ (project root or src/)
```

Special files compose top-down: `error.tsx` catches throws in its segment and below; a deeper `error.tsx` overrides the ancestor. A segment whose children are tabs gives its index `page.tsx` a redirect to the default tab.

### Server Component as the Data Layer

Fetch on the server, pass props to small client islands. The client bundle should contain interactivity, not data fetching.

```tsx
// app/products/[slug]/page.tsx - Server Component
import "server-only";
import { notFound } from "next/navigation";
import { AddToCart } from "./add-to-cart"; // client island

export default async function ProductPage(props: PageProps<"/products/[slug]">) {
  const { slug } = await props.params;
  if (!/^[a-z0-9-]+$/i.test(slug)) notFound();  // validate the param
  const product = await getProduct(slug);        // direct DB or fetch()
  if (!product) notFound();
  return (
    <article>
      <h1>{product.name}</h1>
      <AddToCart productId={product.id} /> {/* only this ships to client */}
    </article>
  );
}
```

Locale prefixes: an `app/[lang]/` segment wraps the localized routes, `generateStaticParams` returns the supported locales, `lang` is validated against that list like any param, and `proxy.ts` redirects unprefixed paths to the negotiated locale.

### Layouts Persist State

Layouts render once for their subtree; only `{children}` changes on navigation - so sidebar scroll, form state, and subscriptions survive. Marking `layout.tsx` `"use client"` purely to hold local state ships the layout and everything it imports to the client and stops it being async, fetching on the server or exporting `metadata`.

```tsx
// Bad - layout and its imports shipped to the client, to hold one filter string
"use client";
export default function Layout({ children }) {
  const [filter, setFilter] = useState("");
  return <div><Sidebar filter={filter} onChange={setFilter} />{children}</div>;
}

// Good - server layout; state lives in the small interactive island
export default function Layout({ children }: LayoutProps<"/dashboard">) {
  return <div><SidebarClient />{children}</div>; // SidebarClient is "use client"
}
```

### Loading and Error UI

```tsx
// app/dashboard/loading.tsx - shown via Suspense while page.tsx awaits
export default function Loading() { return <DashboardSkeleton />; }

// app/dashboard/error.tsx - must be a Client Component
"use client";
export default function Error({ error, retry }: { error: Error & { digest?: string }; retry: () => void }) {
  return <div role="alert"><p>Something went wrong.</p><button onClick={() => retry()}>Try again</button></div>;
}
```

`retry()` re-fetches and re-renders the segment; `reset()` only clears the error state and is the narrow no-refetch case. A Server Component error reaches the client with a generic message; log `error.digest` and match it to the server logs. A segment's `error.tsx` does not catch its own `layout.tsx` - the parent's does; `global-error.tsx` covers the root layout and renders its own `<html>`/`<body>`. For a component-level boundary inside a Client Component, `catchError(Fallback)` from `next/error` gives the same `retry` and lets `redirect()`/`notFound()` pass through, where a hand-rolled React boundary would catch them.

### Parallel and Intercepting Routes

```tsx
// app/dashboard/layout.tsx - slots are typed from the @folders
export default function Layout(props: LayoutProps<"/dashboard">) {
  return <>{props.children}<aside>{props.analytics}{props.notifications}</aside></>;
}
```

Every named `@slot` needs a `default.tsx` or the build fails - return `null` (or call `notFound()`) where the slot should be empty, and render the slot content where it must also appear on hard loads and deep links (a persistent side panel). The implicit `children` slot needs one too when a sibling slot's sub-route is active on a hard load; without it that hard load 404s (the build passes).

`@modal/(.)photo/[id]/page.tsx` intercepts client-side navigations to `photo/[id]` and renders a modal; a direct load, refresh, or shared link resolves the real `photo/[id]/page.tsx`. The marker describes where the intercepted path sits relative to the interceptor - `(.)` same level, `(..)` one up, `(..)(..)` two up, `(...)` from root - not where the navigation started. Both files are mandatory, plus `@modal/default.tsx` returning `null`.

### Proxy and Route Guards

```ts
// proxy.ts at the project root or in src/
import { NextResponse, type NextRequest } from "next/server";

export function proxy(request: NextRequest) {
  const token = request.cookies.get("session")?.value;
  if (!token) return NextResponse.redirect(new URL("/login", request.url));
  return NextResponse.next();
}
export const config = { matcher: ["/dashboard/:path*"] }; // exactly what the body guards
```

With no `matcher`, proxy runs on every request including `_next/static` and images; a matcher wider than the guard buys cost with no protection. Server Actions POST to the page path, so a matcher exclusion also skips them - authorize inside every action. Redirect-if-authed (`/login` for a signed-in user) is the inverse branch of the same proxy. A `middleware.ts` / `export function middleware` is the deprecated name - rename it (codemod `middleware-to-proxy`) and delete any `runtime` config: proxy runs on Node only, and a `runtime` key there throws.

### Navigation

`<Link>` prefetches routes in the viewport (`prefetch`: `"auto"` default, `true`, `false`); `useLinkStatus()` in a `<Link>` descendant gives per-link `{ pending }`. Client Components read the URL with `usePathname`, `useSearchParams` and `useParams`, and navigate imperatively with `useRouter`, all from `next/navigation`. On a prerendered route a Client Component calling `useSearchParams` needs a `<Suspense>` ancestor, or `next build` fails (`missing-suspense-with-csr-bailout`). Under Cache Components, navigating away hides the previous route with `<Activity mode="hidden">` instead of unmounting it: client state survives, Effects clean up and re-run on return, and hidden routes stay in the DOM (`display: none`).

### Caching

With `cacheComponents: true` in `next.config`:

```tsx
// lib/products.ts - any data source (ORM, SDK, fetch); arguments and closures are part of the key
import { cacheLife, cacheTag } from "next/cache";

export async function getProduct(slug: string) {
  "use cache";
  cacheLife("hours");
  cacheTag(`product:${slug}`, "products");
  return db.product.findUnique({ where: { slug }, select: { id: true, name: true, summary: true, coverImage: true } }); // plain, serializable fields
}
```

A `"use cache"` scope cannot read `cookies()`, `headers()` or `searchParams`, even through a helper (`next-request-in-use-cache`, which can pass `next build` and fail at `next start`) - read them outside and pass the value in. Set an explicit `cacheLife` in every scope.

Without `cacheComponents`:

```tsx
const res = await fetch(`${API}/products/${slug}`, {
  next: { revalidate: 3600, tags: [`product:${slug}`, "products"] }, // opt in: fetch is uncached by default
});

import { unstable_cache } from "next/cache";                      // non-fetch sources
export const getProduct = (slug: string) =>
  unstable_cache(() => db.product.findUnique({ where: { slug } }), ["product", slug], {
    revalidate: 3600, tags: [`product:${slug}`, "products"],
  })();
```

`tags` alone only label an entry something else caches. A per-user read is cached correctly when the user id is part of the key - passed as an argument (under `"use cache"`, closed over too) - or under `"use cache: private"`; the defect is reading `cookies()` / `headers()` inside a cache scope, or caching a per-user result under a key that omits the user (module-scope state, a value `unstable_cache` closes over without listing it in `keyParts`). Tags carry the event path; the TTL is the backstop.

Invalidate from a Server Action:

```tsx
"use server";
import { updateTag, revalidatePath } from "next/cache";
import { z } from "zod";
export async function publishProduct(rawId: string) {
  await requireAdmin();
  const id = z.cuid().parse(rawId);      // client input: validate before the query
  const p = await db.product.update({ where: { id }, data: { published: true }, select: { slug: true } });
  updateTag("products");                 // the publisher sees the write on the next render
  revalidatePath(`/products/${p.slug}`); // the real URL is keyed by slug, not id
}
```

Use `revalidateTag("products", "max")` instead when readers may see stale content while it refreshes, and `refresh()` when the write touched no cached tag but the client router must re-render.

### Server Actions: validation, auth, invalidation

```tsx
// app/posts/actions.ts
"use server";
import { updateTag } from "next/cache";
import { z } from "zod";
import { requireUser } from "@/lib/auth";

const CreatePost = z.object({ title: z.string().min(1).max(200), content: z.string().min(1) });

export type State = { error?: Record<string, string[]>; values?: { title: string; content: string }; ok?: boolean }; // type exports are erased, legal in "use server"

export async function createPost(_prev: State | null, formData: FormData): Promise<State> {
  const user = await requireUser();                    // authorize
  const values = { title: String(formData.get("title") ?? ""), content: String(formData.get("content") ?? "") };
  const parsed = CreatePost.safeParse(values);
  if (!parsed.success) return { error: z.flattenError(parsed.error).fieldErrors, values }; // React resets the form after every action: echo the input back
  await db.post.create({ data: { ...parsed.data, authorId: user.id } });
  updateTag("posts");
  return { ok: true };
}
```

Consume with progressive enhancement - the form works without JS:

```tsx
"use client";
import { useActionState } from "react";
import { createPost, type State } from "./actions";

export function CreatePostForm() {
  const [state, action, pending] = useActionState<State | null, FormData>(createPost, null);
  return (
    <form action={action}>
      <input name="title" defaultValue={state?.values?.title} required />
      {state?.error?.title && <p role="alert">{state.error.title[0]}</p>}
      <textarea name="content" defaultValue={state?.values?.content} required />
      <button disabled={pending}>{pending ? "Creating..." : "Create"}</button>
    </form>
  );
}
```

### Route Handlers: when a URL is the product

Use for webhooks, OAuth callbacks, non-JSON responses, or external/non-form clients. Same validation + auth rules as Server Actions. `updateTag` and `refresh` are Server-Action-only and cannot be called here.

```tsx
// app/api/webhooks/stripe/route.ts
import { headers } from "next/headers";
import { revalidateTag } from "next/cache";

export async function POST(req: Request) {
  const sig = (await headers()).get("stripe-signature");
  if (!sig) return new Response("missing signature", { status: 400 });
  const event = verifyStripe(await req.text(), sig); // throws on bad sig
  if (event.type === "product.updated") revalidateTag("products", { expire: 0 }); // "max" when stale is acceptable
  return Response.json({ received: true });
}
```

### Rendering Strategy

| Strategy     | Trigger                                                                                  | Use for                                      |
| ------------ | ---------------------------------------------------------------------------------------- | -------------------------------------------- |
| Static       | No Request-time APIs (with Cache Components, also no uncached data)                      | Marketing, docs, catalog                     |
| ISR          | `"use cache"` + `cacheLife(profile)`; previous model: fetch `next.revalidate` or `unstable_cache` TTL | Periodically changing content    |
| Dynamic      | `cookies()`, `headers()`, `searchParams`, `connection()`                                 | Personalized, auth-gated pages               |
| Streaming    | `<Suspense>` around async children                                                       | Slow data alongside fast shell               |
| Static shell | `cacheComponents: true` + `<Suspense>` over uncached/runtime reads                        | Mostly-static page with a per-user widget    |

Under Cache Components the static shell is the default rendering: everything outside a `<Suspense>` boundary prerenders, and an uncached or runtime read outside one is a blocking-route error in dev and fails the build. Fix it with `<Suspense>`, `"use cache"`, or by moving the read; `export const instant = false` on the segment defers the fix without forcing the route dynamic (synchronous `new Date()` / `Math.random()` / `crypto.randomUUID()` still fail the prerender - use `connection()` + `<Suspense>`).

```tsx
export default function Dashboard() {
  return (
    <>
      <Header />                          {/* prerendered into the shell */}
      <Suspense fallback={<UserSkeleton />}>
        <UserPanel />                     {/* reads cookies(); streams per request */}
      </Suspense>
    </>
  );
}
```

`generateStaticParams()` prerenders a dynamic segment's known paths at build time. Without Cache Components it may return `[]` (or the segment sets `dynamic = "force-static"`), and with `dynamicParams` at its default an unlisted path renders on first request and is cached. With Cache Components it must return at least one param - an empty array fails the build. With no `generateStaticParams` export at all, the segment renders on every request (under Cache Components too, even over `"use cache"` data).

### Metadata API

```tsx
export const metadata: Metadata = { title: "My App", description: "..." };

// Dynamic: share the page's loader - React `cache()` dedupes it within the render, `"use cache"`
// (`unstable_cache` without Cache Components) across requests; an ORM call is not memoized by itself.
export async function generateMetadata(props: PageProps<"/products/[slug]">): Promise<Metadata> {
  const { slug } = await props.params;
  const product = await getProduct(slug);
  if (!product) notFound();               // without this guard an unknown slug is a 500, not a 404
  return { title: product.name, description: product.summary, openGraph: { images: [product.coverImage] } };
}
```

### Image Optimization

```tsx
import Image from "next/image";
import hero from "./hero.jpg"; // colocated static import (public/ stays at the root): dimensions + blur baked in

<Image src={hero} alt="Hero" loading="eager" placeholder="blur" />
<Image src={user.avatarUrl} alt={user.name} width={48} height={48} />
// Remote sources must be allow-listed in next.config.ts `images.remotePatterns`.
```

Defaults that break existing code: `images.qualities` is `[75]`, so any other `quality` is coerced to it until listed; a local `src` with a query string needs `images.localPatterns[].search`; `images.domains` is deprecated for `remotePatterns`, and `priority` for `preload`.

### Pages Router -> App Router Migration

Routes coexist: `pages/` and `app/` ship in the same build, so migrate route-by-route - but the same path in both fails the build (`Conflicting app and page file`). Delete the `pages/` route in the change that adds its `app/` replacement.

| Pages Router                        | App Router equivalent                                                                  |
| ----------------------------------- | -------------------------------------------------------------------------------------- |
| `getStaticProps` / `revalidate: N`  | `"use cache"` + `cacheLife` in a Server Component; previous model: `fetch` `next.revalidate` or `unstable_cache` |
| `getStaticPaths`                    | `generateStaticParams()`                                                               |
| `getServerSideProps`                | Server Component awaiting `cookies()` / `headers()` / `searchParams`                    |
| `getInitialProps` (`_app`/page)     | Server Component fetch, or a layout for shared data                                    |
| Built-in `i18n` config              | `[lang]` segment + `proxy.ts` locale routing (no config-based i18n)                    |
| `_app.tsx` / `_document.tsx`        | Root `app/layout.tsx` (`<html>`/`<body>`, fonts via `next/font`) + per-segment layouts |
| `pages/api/*` API Routes            | `app/api/*/route.ts` Route Handlers, or Server Actions for first-party forms           |
| `next/router` (`useRouter`)         | `next/navigation`: `useRouter`, `useSearchParams`, `usePathname`, `useParams`          |
| `next/head`                         | Metadata API                                                                           |
| `pages/_error.tsx`                  | `app/**/error.tsx` (segment-scoped) + `app/global-error.tsx` (root)                    |

Migration order: shared shell (`_app` -> root layout, `_document` -> `<html>`/`<body>`) first, then leaf routes one at a time, then `pages/api/*`. `next/router` route events (`routeChangeStart`/`routeChangeComplete`) have no `next/navigation` equivalent - replace them with `usePathname`/`useSearchParams` effects, or `<Link onNavigate>` and `useLinkStatus` for per-link signals.

## Output Format

When designing, emit the Route Map, the Mutations list and the File Tree below, then one finding block per risk in the design (Location names the planned file, no line). When auditing, emit the finding blocks alone, ordered by severity, then the `Not assessed:` and `Notes:` lines; a consuming workflow owns the envelope and summary. Fix references a Pattern by name, or the governing Rule when no Pattern covers it.

Route Map rows: an intercepted URL takes two rows (soft-nav modal, hard-load page); a parallel slot uses `@slot` as Path (`@slot/segment` for its nested segment); an absent Loading/Error artifact is `None`; a component not in the read set is `(not shown)`. Auth records enforced behaviour - a broken guard is `Public` plus a finding; a guard that fails open only on an edge case keeps its value and takes a finding at the severity of what gets through.

```
### Route Map

| Path | Component | Layout | Loading | Error | Auth | Strategy | Cache |
| ---- | --------- | ------ | ------- | ----- | ---- | -------- | ----- |
| ... | ... | <nearest layout> | ... | ... | {Public \| Protected \| Protected (role: <role>[ or <role>]) \| Public (redirect-if-authed)} | {Static \| ISR \| Dynamic \| Streaming \| Static shell} | {mechanism with cacheLife or TTL and tags \| none} |

### Mutations

- <Server Action or Route Handler> - Invalidates: {`updateTag(<tag>)` | `revalidateTag(<tag>, <profile>)` | `revalidatePath(<path>)` | none - touches no cached surface[; `refresh()` re-renders the router]}

### File Tree

{the `app/` skeleton the Route Map implies, `proxy.ts` and its `matcher` included}

- Location: <file>[:<line>]
  Issue: {RscBoundary | ClientLeak | ServerOnlyImport | UseClientAtRoot | ServerActionAuth | ServerActionValidation | ServerOnlyExport | OrmRowToClient | CachingMisuse | MissingRevalidation | DynamicWithoutSuspense | CacheComponentsConflict | DeprecatedApi | MetadataManual | ImageRaw | NavigationPush | ParamsNotAwaited | UnvalidatedParam | ErrorBoundaryGap | MissingLoadingUi | ParallelSlot | LayoutRefetch | RouteGuardGap | ProxyOverreach | RouteConflict | LegacyRouterInApp | LegacyI18nConfig | MigrationOrder}
  Severity: {Blocker | High | Medium | Low}
  Evidence: <quoted snippet or symbol>
  Fix: <one-line action; reference a Pattern by name, or the governing Rule>

Not assessed: {input the review needed but never saw - a file referenced but not provided, a module whose behaviour decides a severity; never a guessed finding; omit when none}

Notes: {handoffs and off-enum observations, each naming the owning concern; omit when none}
```

Issue definitions, where the name is not enough:

- `CachingMisuse`: a wrong caching choice - shared cacheable data left uncached, a missing TTL, per-user data under a key that omits the user, a request-time read (`cookies()` / `headers()` / `searchParams`) inside a `"use cache"` or `unstable_cache` scope; without the flag also `dynamic = "force-dynamic"` or `cache: "no-store"` on data that changes periodically.
- `MissingRevalidation`: a Server Action or Route Handler write to a cached surface with no following `updateTag` / `revalidateTag` / `revalidatePath`, so cached views stay stale; a `refresh()` alone does not count.
- `CacheComponentsConflict`: under `cacheComponents`, a removed segment export (`dynamic`, `revalidate`, `fetchCache`, `dynamicParams`), `runtime = "edge"`, or `generateStaticParams` returning `[]`; without it, `"use cache"` / `cacheLife` / `cacheTag` in use.
- `DynamicWithoutSuspense`: an uncached or request-time read, or a Client Component's `useSearchParams` on a prerendered route, with no `<Suspense>` (or `loading.tsx`) above it. `useSearchParams`, and any such read under `cacheComponents`, fails `next build`; otherwise it holds the whole route until the read resolves.
- `DeprecatedApi`: one-argument `revalidateTag(tag)` (a type error that behaves like `{ expire: 0 }`), `middleware.ts` / `export function middleware`, `next/image` `priority`, `images.domains`.
- `ServerOnlyExport`: a `"use server"` file exporting an async function not meant as an endpoint - every exported async function is network-callable (a non-async export fails the build, so it is not this finding). An unauthorized exported helper is `ServerOnlyExport` when never meant as an endpoint, `ServerActionAuth` when it was. Both action codes cover Route Handlers too; Location may list two files when the defect spans them.
- `OrmRowToClient`: a raw ORM row passed as a prop into a Client Component.
- `ErrorBoundaryGap`: a failing segment with no `error.tsx` above it, `error.tsx` without `"use client"`, a hand-rolled boundary catching `redirect()` / `notFound()` (use `catchError`), or a `reset()`-only fallback over fetched data.
- `NavigationPush`: imperative navigation where `<Link>` fits - `router.push`, or `window.location` / a bare `<a href>` to an internal route.
- `RouteGuardGap`: a guard that fails open (including one rendering children while its check is pending), proxy-only auth with no page or data-layer re-check, or client-side auth duplicating what proxy or the page should own. A guard failing open only on an edge case is scored by what that edge case lets through.
- `ProxyOverreach`: DB, network or heavy work in `proxy.ts`, or a `matcher` wider than the guard.
- `ParallelSlot`: a slot without `default.tsx` (one finding per layout listing every such slot), a slot the layout never renders, or an interceptor without its hard-load page.
- Migration: `RouteConflict` = same path in `pages/` and `app/`; `LegacyRouterInApp` = `next/router` or its route events inside `app/` (crashes at mount, listeners never fire); `LegacyI18nConfig` = config-based i18n serving App Router routes; `MigrationOrder` = `_app`/`_document` still authoritative (fonts or `<html>` diverging from `app/layout.tsx`) while `app/` routes ship.

Severity:

- **Blocker**: anything that fails `next build` or crashes at runtime (`CacheComponentsConflict`; one-argument `revalidateTag` as `DeprecatedApi`; a named `@slot` without `default.tsx` as `ParallelSlot`; `DynamicWithoutSuspense` that fails the build; `error.tsx` without `"use client"` as `ErrorBoundaryGap`; an async Client Component as `RscBoundary`; `RouteConflict`; `LegacyRouterInApp`); server-only import or ORM/secret leak into a client bundle (`ServerOnlyImport` with the client import observed; `ClientLeak`; `OrmRowToClient` when the row carries secret fields); missing auth on a mutating Server Action or one returning per-user data; `params` / `searchParams` / `cookies()` used without `await` (`ParamsNotAwaited`); `ServerOnlyExport`; per-user data under a key that omits the user, or a request-time read inside a cache scope (`CachingMisuse`); DB or network work in proxy on every matched request (`ProxyOverreach`).
- **High**: `UseClientAtRoot` (a page/layout root that needs no interactivity, a client layout holding trivial state included - an extractable leaf listener does not count as needing it); missing input validation on an action (`ServerActionValidation`); `MissingRevalidation` after a write; `DynamicWithoutSuspense` that only blocks streaming (no `cacheComponents`, or deferred by `instant = false`); `OrmRowToClient` without secret fields; `ErrorBoundaryGap` on a fetching segment, a hand-rolled boundary catching `redirect()` / `notFound()`, or a `reset()`-only fallback over fetched data; `RouteGuardGap` that fails open; `ParallelSlot` never rendered, missing its hard-load page, or a missing `children` `default.tsx`; `UnvalidatedParam` reaching an ORM, an HTTP client URL or a file path; `LegacyI18nConfig`.
- **Medium**: `CachingMisuse`; `ServerOnlyImport` for a missing `import "server-only"` guard with no observed client import; `RscBoundary` (a client component fetching what a parent Server Component could pass down); `MissingLoadingUi`; `LayoutRefetch`; `RouteGuardGap` duplicating auth client-side; `ProxyOverreach` for an over-broad `matcher` with cheap logic, or heavy parsing on matched requests; `DeprecatedApi` other than `revalidateTag`; `NavigationPush` via `window.location` or a bare `<a href>`; `MigrationOrder`; `MetadataManual`; `ImageRaw`; `UnvalidatedParam` elsewhere.
- **Low**: `NavigationPush` via `router.push`; minor convention drift.

No Issue value is left unscored. Where a value appears in more than one band, the band naming your defect's condition wins; where two fit equally, take the higher.

App Router = an `app/` or `src/app/` directory with a root layout (`layout.{tsx,jsx,js}` at its top, or atop each route group). Beside `pages/` the tree is hybrid: the App Router rules apply to `app/`, and `pages/` routes are audited against the migration table only. A `pages/`-only project with no migration in scope emits `No Next.js findings (not App Router).`

## Avoid

- Mutating data from a Route Handler that a first-party form could call as a Server Action - duplicates validation, loses progressive enhancement.
- Fetching in a Client Component when the parent Server Component could pass props - extra round trip, ships fetch code, breaks streaming.
- Returning a raw ORM row (`prisma.user.findUnique(...)`) into a Client Component - leaks fields like `passwordHash` into the HTML payload.
