# Domain Knowledge-Base Layout

The single source of truth for where every artifact of a domain knowledge base lives, what shape it has, and who may rewrite it. `task-domain-sync` writes the generated layer and seeds the curated one; `domain-kb-ingest` writes the curated layer; `task-domain-explain`, `task-domain-ask`, and `task-domain-solve` read both (`task-domain-ask` saves through `domain-kb-ingest`).

## When to Use

- `task-domain-sync` refreshing (no command, `update`), building or regenerating (`init`), or importing into (`import`) the knowledge base
- `domain-kb-ingest` placing a fact or document into the curated layer
- `task-domain-explain`, `task-domain-ask`, and `task-domain-solve` locating a card, the atlas, the ledger, a curated doc, or the reverse index
- Invoked standalone: verify an existing knowledge base against this contract, write nothing, and emit the Output Format block

## Rules

- **Root is the project the plugin runs in.** The knowledge base lives at the project root; service repositories live under `repos/<repo>/` (submodules or plain clones). The repo set is the directories under `repos/`. Nothing under `repos/` is counted or verified, and nothing there is written except by the sync Fetch step: remote-tracking refs, the guarded checkout bump, and, for a repo `.gitmodules` lists, the gitlink `git add repos/<repo>` in the root (a plain clone has no gitlink to stage); never a commit. A knowledge base is synced when `_index/sync-state.json` records a `sha` for at least one repo; `init` on a synced root regenerates every generated file with the carried parts below, and on any root leaves a populated curated layer untouched.
- **Two layers share the root.** The generated layer is every path the table below marks `regenerate`, `mark`, or `index`. Its Markdown files carry frontmatter `generated: domain-sync` and end with `## Notes`, except the three root files (`CLAUDE.md`, `index.md`, `ATLAS.md`), which are generated by path and carry no frontmatter, and the `index` files, which carry neither. The curated layer is every Markdown file under the curated folders in the table below; curated means a person vouches for the fact, whatever its source (a paste, an imported document, or a commit the Distil pass distilled), so the layer is written only by a person or through `domain-kb-ingest` (which the Distil pass and `import` call), and no other pass regenerates, adopts, or deletes it; sync reads it and links to it. `README.md`, `.gitignore`, and `_templates/` are scaffolding, in neither layer; any other Markdown file outside `repos/`, `tmp/`, and dot-folders (`.claude/`, `.github/`) is outside both layers. The two layers are split by who may rewrite a file, not by where a fact came from; readers see them merged through `index.md`, the `Doc` columns, the cards' `doc:` entries, and the lessons. A file without `generated: domain-sync` at a generated Markdown path below the root (`ledger/rules.md`, `overview/glossary.md`; the `_index/` files carry no frontmatter and are exempt) stops the sync preflight with `generated path occupied by a curated file - move it (context/ is the usual home) or delete it`; it is never overwritten and never carried into `## Notes`.
- **Every path has its write modes** (table below). `regenerate` rewrites the whole file and carries the protected parts; `mark` edits these fields in place and nothing else, on any generated Markdown file whatever its table mode for the first and last: frontmatter `freshness`, a card's `## Changed since`, `priority`, `ranked_by`, the `Id` numbers that replace `R-new` and `D-new`, a Rules row's `Doc`, `Rationale`, `Confidence` (when the chain strengthens them) and `Quirk` (from every chain walk), a `flow to trace:` Related entry replaced by `<capability>/<flow>` once that card exists, `doc:` and `consumer:` Related entries, Contract `Callers`, the corroboration fields (Runtime lines, `Exercised in traces` cells, `verified_by_trace`, a `(from observability tool)` monitor name, which replaces a `none - ...` Monitors form and the `Detected by` cells that repeated it, an Error tracker `; alert rules: ...` suffix, `deploy` rows in Recent changes, a `trace differs` Debt row), and a line appended to a generated file's `## Notes`; a capability's Flows `Priority` and `Status` cells; `CLAUDE.md` `## Capabilities` when the Discover pass fills it and its `## Repos` table at an `import` Finalise; ledger and register `Doc` cells and the contract `Doc` line, the ledger rows the Link pass adds (numbered on the spot after the highest id, their chain blocks appended to `chains.md`, and copied to `unknown-rationale.md` when unknown), and playbook `Past incidents` cells; and ATLAS Status cells, counts line, `### Untraced` rows, `## Unmapped changes` rows, and the `## Citation drift` table, which each Verify pass rewrites whole. `index` rewrites a file whole with no frontmatter. `seed` creates the path with its template (or `.gitkeep` for a folder) only when absent and never touches it again, except that Finalise deletes a seeded `.gitkeep` once its folder holds a Markdown file. `never` touches nothing.
- **Carried on regenerate:** the `## Notes` section, which is always the last section and runs to end of file; in `CLAUDE.md`, the `## Observability`, `## Audience`, `## Capabilities`, `## Solve`, and `## Precedence` sections and the `Branch` and `Scope` cells of `## Repos`; `## Unmapped changes` and `## Citation drift` in `ATLAS.md` (the latter as the Verify pass of the same run left it); the frontmatter `aliases` list (union of old and new), `priority`, and every `R-n` or `D-n` id whose row persists. Every regenerated file ends with `## Notes`, emitted empty when there is nothing to carry.
- **Two status vocabularies.** A generated file's frontmatter carries `freshness: current | stale | orphaned`, which says whether it matches the code. A curated file's frontmatter carries `status: draft | active | deprecated`, which says whether people still vouch for it; a `deprecated` doc names its replacement in `superseded_by`. Neither key appears on the other layer, and verification checks each by layer. An ADR's `> Status:` line is the decision's own state, independent of `status`: the body of an `accepted` ADR is never edited; a later ADR supersedes it, and only then does the old one's line become `superseded` and its frontmatter `status: deprecated` with `superseded_by`.
- **Orphans.** A generated file whose source vanished (a flow whose trigger surface the Discover pass no longer finds, a caller no longer seen, a repo directory removed) gets `freshness: orphaned`, its body frozen and its reverse-index entries removed; `update` leaves it alone unless the Discover pass matches a trigger to it again, when it is re-traced as a stale card; `init` deletes it, at Finalise, only when its `## Notes` is empty. `orphaned` outranks `stale`.
- **Ids are stable.** An id is kebab-case, assigned at creation, never renamed by sync; `caller-` is prefixed to a caller contract's file and id when the name collides with a repo or capability. A flow is re-identified by its Trigger `Surface`, then by the majority of its reverse-index files (ties keep the older card); a changed business name becomes an alias. A rule row keeps its id while its enforcement site (file plus rule text) persists, then by rule text alone; a debt row keeps its id while a prior row has the same `Location` file (line ignored) and the same `Signal` class; new ids take the next number after the highest in use. Flows are unique within a capability and referenced everywhere as `<capability>/<flow>`.
- **Surfaces match whole.** Wherever a surface is compared (`Used by flows`, `Related`, `flow to trace:` resolution), the whole surface string is one token, method and host tag included, with a trailing ` - file:line` and any parenthetical note stripped (an outbound client's `(<base config key>)` is kept, being part of its identity); a message hop `<topic>: <publisher> -> <consumer>` matches by its `<topic>`; a surface never matches as a substring of a longer path, and `/`, `ANY /`, or any single-segment surface matches only a hop or trigger written exactly so.
- **Empty is explicit** in the generated layer (a curated section nobody answered keeps its template heading and no body). A slot with no value reads `none - <evidence>`, `unknown - not discoverable from the repos`, or `unavailable - <reason>`; a slot whose enum lists `none` reads `none`. A table with no rows keeps its header and one row whose first cell reads `none - <evidence>` and whose other cells are empty; a list section with no items reads `- none - <evidence>`. A conditional section (`## Contract`) exists only when its condition holds and is never drift when absent.
- **Nothing invented.** Monitors, dashboards, job names, hostnames and channels are cited from a file path or config key, or from the observability tool's own list marked `(from observability tool)`, or written `unknown - not discoverable from the repos`. A curated doc is evidence when it states the fact; it is cited by path.
- **Languages.** `CLAUDE.md` `## Audience` `Language:` is a comma-separated list of ISO 639-1 codes; the first is the output language of every generated file and every answer, and every listed code is a search language for curated docs, `Also called` aliases, and pasted input. When the list has a second code, the `**Story:**` line of each flow card carries a second sentence in it, and `task-domain-ask` answers stakeholder-shaped inputs in it as well as in the first. Nothing else is translated; a third code adds search coverage only. A search in every listed language looks up code identifiers, surface strings, constants, and ids verbatim, and each business noun or phrase translated into each listed code.
- **Never commit.** Files are written to the working tree; the user versions them.

## Patterns

### Layout and write modes

```
CLAUDE.md                      regenerate, mark   how agents use this KB; Repos, Observability, Audience, Capabilities, Solve, Precedence
index.md                       regenerate         agent entry: Need table, generated files, curated docs, retrieval hints
ATLAS.md                       regenerate, mark   human entry: learning path, capabilities, untraced, stale marks, unmapped changes, citation drift
README.md                      seed               folder purposes and the curated frontmatter, for people
.gitignore                     seed               tmp/, .DS_Store, .claude/settings.local.json
overview/domain-model.md       regenerate         actors, core entities, value flow, external systems
overview/state-machines.md     regenerate         lifecycle entities: transition graph and the guard on each edge
overview/glossary.md           regenerate         Term | Also called | Code identifier | Flows
overview/not-supported.md      regenerate         what the system deliberately does not do, with evidence
capabilities/<capability>/capability.md        regenerate, mark   owning services, flows, monitors, top risks; exists only once the capability has a card
capabilities/<capability>/flows/<flow>.md      regenerate, mark   one flow card per end-to-end business flow
ledger/rules.md                regenerate, mark   every rule with kind, site, flows, doc, rationale, confidence, quirk
ledger/unknown-rationale.md    regenerate, mark   the ledger rows whose confidence is unknown
ledger/chains.md               regenerate, mark   one `## R-n` block per rule: the evidence chain behind its rationale
playbook/by-symptom.md         regenerate, mark   symptom -> flows -> first checks -> past incidents
contracts/<caller>.md          regenerate, mark   per integrating caller: consumer doc, surfaces used, sharp edges
debt/register.md               regenerate, mark   trace-evidenced and history-evidenced debt with severity, category, doc
debt/detection-gaps.md         regenerate         flows with no signal or capture only
debt/recent-risk.md            regenerate         flows with 3 or more commits in the window
surfaces/<repo>.md             regenerate         surface inventory per repo, each trigger row with its capability and Used by flows
_index/file-to-flow.json       index              source file -> flow ids, rebuilt from the `files` list of every non-orphaned card
_index/sync-state.json         index              version; synced; window; fetch; in_progress; curated; repo -> path, synced SHA, branch, scope, stack, database, surface count
_index/last-sync.md            index              the last sync command's full report block, verbatim
_templates/<name>.md           seed               the nine templates below; ingest copies from here
rules/ specs/services/ specs/data-flow/ incidents/ tech-debt/ adr/ consumers/ patterns/ context/   seed   curated; .gitkeep when empty
repos/<repo>/                  never              the service repositories (Fetch step excepted, per Rules)
```

`debt/` (generated: what the traces and history evidence) and `tech-debt/` (curated: what people recorded, with severity and recommendation) are distinct folders by design; the register's `Doc` column joins them. `patterns/` holds the conventions agents follow when they implement or review in these repos; the plugin seeds it, and only `domain-kb-ingest` (a person's input, or a convention Distil or `import` distils) places conventions into it.

### Curated layer

| Folder              | Holds                                                                                  | Template          |
| ------------------- | -------------------------------------------------------------------------------------- | ----------------- |
| `rules/`            | One business, process, policy, or rollout-gate rule per file, with scope and exceptions | `business-rule.md` |
| `specs/services/`   | One service or integrating app per file: purpose, ownership, API, data, key behaviours  | `service.md`      |
| `specs/data-flow/`  | One cross-service end-to-end flow per file as people describe it                        | `data-flow.md`    |
| `incidents/`        | One production incident per file, named `YYYY-MM-DD-<slug>.md` (`undated-<slug>.md` when the date is unknown) | `incident.md`     |
| `tech-debt/`        | One file per service or area listing debt items with severity and recommendation        | `tech-debt.md`    |
| `adr/`              | One decision per file, named `NNNN-<slug>.md`; accepted ADRs are immutable              | `adr.md`          |
| `consumers/`        | One integrating party with no repo under `repos/` per file, named after the caller      | `consumer.md`     |
| `patterns/`         | One reusable convention per file                                                        | `pattern.md`      |
| `context/`          | Background, history, and rationale packs; never the source of truth for a rule          | `context-pack.md` |

A curated file other than an incident or an ADR is named by the kebab-case of its title (`rules/refund-window.md`); an incident takes the date it happened.

Frontmatter on every curated file:

```yaml
---
title: Refund window
status: active                 # draft | active | deprecated
created: 2026-09-01
updated: 2026-09-26
tags: [rule, refunds]          # the kind first, then topics
imported_from: ../old-kb/rules/refund-window.md   # only on imported files: the --in path as typed, joined with the file's path relative to it
supersedes: []                 # optional
superseded_by: rules/refund-window-v2.md          # required when status is deprecated
severity: high                 # incidents only
---
```

`README.md` is seeded with one sentence defining the two layers (generated: rewritten from code by sync; curated: vouched for by a person, written only through ingest), the folder table above, the frontmatter block, and one line each naming `task-domain-sync import` as the way to add a fact or a document and `task-domain-ask` as the way to query. `.gitignore` is seeded with `tmp/`, `.DS_Store`, and `.claude/settings.local.json`. A `.gitkeep` is removed from a curated folder at Finalise once it holds a Markdown file.

### Templates

Scaffold writes these nine files to `_templates/`, each starting with the frontmatter block above reduced to `title`, `status`, `created`, `updated`, and `tags` (values as `{slots}` named after the key, `title: {title}`; `incident.md` adds `severity`) and an H1 `# {Title}` (`# ADR {NNNN}: {Title}` for the ADR); `domain-kb-ingest` copies the matching one when it creates a file, so a project edits its templates and the plugin follows. A field group named in parentheses is written as `- **Label:** value` bullets. Section skeletons, in order:

- `business-rule.md`: `## Statement` (one sentence, then `> **IF** ... **THEN** ... **ELSE** ...`), `## Rationale`, `## Scope` (`Applies to`, `Does NOT apply to`), `## Parameters` (`| Parameter | Value | Unit | Notes |`), `## Examples` (`Allowed`, `Rejected`), `## Enforcement` (`Kind: {code | process | policy | rollout gate}`, `Where enforced: {file:line | process - <where>}`, `Validation type: {hard block | soft warning | async check | review gate}`), `## Exceptions` (`| Exception | Condition | Approved by |`), `## Operational notes`, `## Related docs`.
- `service.md`: `## Purpose`, `## Ownership` (Team, Repo, Runtime), `## Responsibilities`, `## Dependencies` (`| Dependency | Type | Direction | Purpose |`), `## API surface` (`| Endpoint / Topic | Method / Protocol | Description |`), `## Data stores`, `## Key behaviors` (Idempotency, Retry strategy, Failure mode), `## Related docs`.
- `data-flow.md`: `## Summary`, `## Trigger`, `## Steps` (`| # | Actor | Action | Target | Data |`), `## Diagram` (Mermaid), `## Error scenarios` (`| Failure point | Cause | System behavior | Recovery |`), `## Business rules applied` (links to `rules/`), `## Related docs`.
- `incident.md`: frontmatter adds `severity`; `## Summary`, `## Timeline` (`| Time ({tz}) | Event |`), `## Impact` (Duration, Users affected, Financial impact, Data impact), `## Root cause`, `## Detection`, `## Resolution`, `## Action items` (`| # | Action | Owner | Due | Status |`), `## Lessons learned`, `## Related docs`.
- `tech-debt.md`: `## Summary`, `## Items` with one `### {Severity} - {Title}` block per item (`Category`, `Location`, `Signal`, `Risk`, `Recommendation`), `## Security & compliance`, `## Related docs`.
- `context-pack.md`: `## Background`, `## Key concepts`, `## How it works today`, `## Known risks`, `## Historical decisions` (`| Decision | Date | Why | Link |`), `## Open questions`, `## Related docs`.
- `pattern.md`: `## Problem`, `## Context`, `## Solution`, `## Implementation`, `## Trade-offs` (`| Benefit | Cost |`), `## Known usage`, `## Related docs`.
- `adr.md`: H1 `# ADR {NNNN}: {Title}`, `> Status: {proposed | accepted | superseded}`, `## Context`, `## Decision`, `## Consequences`, `## Alternatives considered`, `## Related docs`.
- `consumer.md`: `## Who` (team or system, contact), `## Integration` (`| Surface used | Direction | Protocol | Purpose |`), `## Sharp edges`, `## Webhooks and callbacks`, `## Related docs`.

### Sync passes

`init` and `update` run these passes in order. `import` runs Scaffold (`_templates/` only) and Distil on its input, then, on a synced root, Link, Verify citations, Finalise (`index.md`, `.gitkeep` removal, the `CLAUDE.md` `## Repos` table), and Record. At the start of each pass a command writes `in_progress: {command}:{pass}` (the pass name as listed, `init:Scaffold`) to `sync-state.json`, which Scaffold creates with it on a first `init`, the only write to that file between Scaffold and Record, and Record clears it; `import` on an unsynced root writes no `sync-state.json`, so `in_progress` is never set there; a sync command started while it is set resumes the recorded command at that pass instead of running its own; the reading workflows stop.

1. **Scaffold** (`init`): absent root files with header-only tables, no list items, and header bullets reading `0` or `none - not yet synced`, the one exception to the empty form (Finalise fills them in the same run; an existing root file regenerates there with its carried parts), an absent `CLAUDE.md` getting its `## Repos` rows with `Branch` and `Scope`, `## Observability` from the repos' tracing and error-tracker initialisation, and the fixed `## Audience`, `## Solve`, and `## Precedence` text, `overview/` stubs (generated frontmatter, H1, section headings, header-only tables), every `seed` path that is absent (`README.md`, `.gitignore`, `_templates/`, the curated folders with `.gitkeep`), `sync-state.json` with every repo's stack note, database, branch and scope, `window`, `fetch` `false`, and every recorded `sha` kept, `null` where none is recorded. `update` skips this pass; `import` runs only its `_templates/` seeding.
2. **Fetch** (`init`, `update`; skipped by `--no-fetch`): fetch each repo's tracked branch and apply the guarded bump the sync skill defines; the tip the run records is the checkout `HEAD` after this pass.
3. **Mark** (`update` only): the Stale marking recipe. The recorded `sha` is not advanced here. A repo with no recorded `sha` has no diff; its triggers are traced as on `init`.
4. **Discover**: `domain-surface-discovery` runs over every repo with the repo's scope and writes `surfaces/<repo>.md` where its files or rows changed, carrying `Used by flows` for rows that persist, and proposes the capability set (in `domain-surface-discovery`'s assignment order: `infrastructure` triggers first, then `CLAUDE.md` `## Capabilities`, then one capability per business area the handler modules name; authentication and token issuance, API docs, admin and background-job consoles, staff and role management, and maintenance-status triggers are `infrastructure`, never a capability, and get no card and no `### Untraced` row), each trigger assigned to one. A file the Discover pass reports under `Placed` removes its ATLAS `## Unmapped changes` row. A card is marked `orphaned` only when the Ids rule (Trigger `Surface`, then the majority of its reverse-index files) matches it to no discovered trigger.
5. **Trace**: one flow card per due trigger (`init`), or per stale or missing card (`update`), bounded by `--capabilities` and `--max-flows`; a `ui screen`, `public api`, `webhook in`, or `schedule` trigger, and a `message` no card crosses as a hop, is due a card, while an `internal api` row or a crossed `message` is a hop inside its card; a due trigger left without a card is `missing` and sits in ATLAS `### Untraced`. Rule and debt rows are written as `R-new` and `D-new`; `file-to-flow.json` is rebuilt from the `files` list of every non-orphaned card.
6. **Distil** (`update`; `import` ingests its input here): commit-window changes become cited candidate facts routed through `domain-kb-ingest` into the curated layer.
7. **Rank**: `priority` and `ranked_by` on every card (a `mark`) by the tiers below.
8. **Analyse**: `ledger/` (rules, unknown-rationale, chains via `domain-rationale-chain`), `playbook/`, `contracts/` (callers of each surface, from the cards' hop lists and Contract sections), `debt/` (`Location` from each card's Debt row, `Fix` and `Detection` written here as the change and the signal that would close it); then `surfaces/` regenerated with `Used by flows`, and in the cards (a `mark`) `R-new` / `D-new` replaced by numbers, `flow to trace:` entries replaced by `<capability>/<flow>` where the card now exists (exact surface match), and Contract `Callers` filled from `contracts/`.
9. **Link**: the generated layer is pointed at the curated docs that name its surfaces, rules, locations, and callers: ledger rows and `Doc` cells from `rules/`, register `Doc` from `tech-debt/`, contract `Doc` from `consumers/`, playbook `Past incidents` from `incidents/`, card `## Related` `doc:` and `consumer:` entries. Curated files are read, never written.
10. **Verify citations** (read-only): every `repos/<repo>/<path>:<line>` in the curated layer is checked against the tip this run records (the recorded `sha` for `import`): the cited line as it read at the newest first-parent commit of the tracked branch on or before the end of the day the citation was written into the doc (the earlier of the oldest commit `git log -S` on the doc lists for the citation string and the doc's `created` date) is `verified` when the tip holds the same text on that line, `moved` when on another line of the file, `gone` when nowhere in it (a baseline line that is blank, or a file absent at the baseline, is replaced by what the doc's sentence names, looked for at the tip); ATLAS `## Citation drift` is rewritten whole from the result; no doc is edited.
11. **Finalise**: `init` first deletes every orphan whose `## Notes` is empty; then `capability.md` for every capability with at least one card, `overview/`, and the root files regenerate with the final tables; `index.md` `## Curated` is rebuilt from every curated doc's frontmatter; a `.gitkeep` in a curated folder holding a Markdown file is removed.
12. **Record**: `sync-state.json` rewritten whole and `_index/last-sync.md` written with the command's full report block.

**Rank tiers.** Tier `moves money`: a flow whose State changes or Side effects charge, capture, refund, pay out, deposit, or issue an invoice. Tier `grants access`: a flow that grants access or changes a limit. Then `most changed` (3 or more commits in the window over the card's `files`), then `most incidents` (at least one incident naming the flow), then `unranked`. Inside every tier: in-degree first (how many other cards name the flow under `## Related`, a `flow to trace:` entry whose surface equals its Trigger Surface included), then incidents naming it, then commits, then trigger order. The ATLAS learning path names the tier for every capability.

### Ids and references

| File                        | Id                                                                     | Frontmatter `id`             |
| --------------------------- | ---------------------------------------------------------------------- | ---------------------------- |
| root files                  | the file name (`CLAUDE.md`, `index.md`, `ATLAS.md`)                    | none; generated by path      |
| overview files              | `domain-model`, `state-machines`, `glossary`, `not-supported`          | as named                     |
| capability                  | directory name                                                         | `<capability>`               |
| flow                        | file name without `.md`                                                | `<flow>`, plus `capability:` |
| caller contract             | file name without `.md`                                                | as named                     |
| ledger, playbook, debt, surfaces | file name without `.md`; surfaces as `surface-<repo>`             | as named                     |
| rule row, debt row          | `R-<n>`, `D-<n>`                                                       | column `Id`                  |
| curated doc            | its root-relative path                                                 | none; `title` names it       |

The examples in this file group the refund flow under `payments`, a grouping a project sets through `## Capabilities`; the discovery rule alone would name it by its handler module. Every `Flows` column, every reverse-index value, every ATLAS row, and every flow entry under `Related` that has a card uses `<capability>/<flow>` (a hand-off with no card yet reads `flow to trace: <kind>: <surface>`); ATLAS links it to `capabilities/<capability>/flows/<flow>.md`. A curated doc is referenced by root-relative path everywhere in the generated layer, and by a Markdown link relative to the citing doc inside another curated doc (`../rules/refund-window.md` from `incidents/`, `../tech-debt/orders.md#high---retry-loop` for the item `### High - Retry loop`). Every `file:line` is root-relative under `repos/` (`repos/orders/app/services/refund_service.rb:18`); line numbers refresh only when the file is regenerated. A trigger cell reads `<kind>: <surface>`. A `Surface` slot ends with `- file:line`.

### Generated-file frontmatter

```yaml
---
generated: domain-sync
id: order-refund
freshness: current             # current | stale | orphaned
synced: 2026-09-26
sources:                       # repo@sha, first 7 characters of `git rev-parse HEAD` when the file was written
  - orders@3f2a1c9
  - payments@b77e0d2
aliases: []                    # business names this artifact was known by
---
```

Flow cards append `capability: <capability>`, `priority: <integer>` (rank across all flows, 1 first to learn, `0` until ranked; unranked sorts last), `ranked_by: {moves money | grants access | most changed | most incidents | unranked}` (`unranked` until ranked), `verified_by_trace: <true | false>` (`true` only when a runtime trace matched the hop list hop for hop), and `files:`, the root-relative list of every repo file the card cites, which is the card's contribution to `file-to-flow.json`. `freshness: stale` is set only on flow cards.

### CLAUDE.md

```markdown
# {Domain} knowledge base

{One paragraph: what the domain does, which repos it spans, and that agents read `index.md` first and `_index/file-to-flow.json` to map a file or stack trace to a flow.}

## Repos

| Repo | Path | Stack | Database | Branch | Scope | Synced SHA |
| ---- | ---- | ----- | -------- | ------ | ----- | ---------- |

## Observability

- **Tracing:** {tool | none}
- **Errors:** {tool | none}
- **Services:** {service names as the tracing or error config declares them, or unknown - not discoverable from the repos}

## Audience

- **Language:** en
- **Readers:** the tech lead

## Capabilities

| Capability | Triggers |
| ---------- | -------- |

## Solve

- **Implement skill:** unknown - set in CLAUDE.md ## Solve
- **Test skill:** unknown - set in CLAUDE.md ## Solve
- **Test command:** unknown - set in CLAUDE.md ## Solve
- **Conventions file:** unknown - set in CLAUDE.md ## Solve
- **PR draft path:** tmp/pr.md
- **Base branch:** main

## Precedence

When sources disagree: curated `rules/` > curated `specs/` > generated cards > curated `context/`. A card citation, read from the code at the last sync, outranks any doc claim it contradicts; the disagreement is reported as drift and never resolved silently. `context/` is background, never the source of truth.

## Notes
```

Every section but `## Precedence`, which is read whole, and `## Notes`, which is free text, is parsed by the narrow-read rule: the named heading, then `- **Key:** value` lines or the table, nothing else. `## Repos` mirrors `sync-state.json`, which is authoritative (`Synced SHA` as its first 7 characters), except `Branch` and `Scope`, which the user edits here and sync copies into the state: `Branch` is the `.gitmodules` `branch` for the repo (`.` meaning the root's current branch), else `origin/HEAD`'s target, else `HEAD` with a warning; `Scope` is `all`, or `include=<regex>` matched against repo-relative paths, optionally followed by `; tables=<regex>` matched against table names in migrations and schema files. `Tracing` and `Errors` come from the tracing and error-tracker initialisation in the repos (`none` when absent); an existing section wins. `## Audience`, `## Solve`, and `## Precedence` are written by scaffold with the text shown and carried verbatim afterwards; the user edits the first two, and a `## Solve` value may name any skill installed in the consuming project. A carried section (`## Precedence` included) is compared to nothing: text that differs from the scaffold text is a user edit, never drift; a listed key is read by its name and an unlisted `- **Key:**` line is read by nobody. `## Capabilities` is written by the Discover pass whenever it has no rows, from that pass's proposals (one row per capability, `Triggers` holding surface patterns such as `POST /api/orders*`), and carried verbatim once it has any; a trigger matching a row's pattern takes that capability before any rule but `infrastructure`, so the user steers grouping by editing the table.

### Overview files

Each has an H1 and these sections, in order, then `## Notes`.

- `domain-model.md`: `## Actors` (`| Actor | Kind | Does |`, kind `{person | system}`), `## Entities` (`| Entity | Owned by | Lifecycle | Key relations |`), `## Value flow` (one paragraph and a Mermaid flowchart of money or work moving between actors and services), `## External systems` (`| System | Direction | Used by flows | Integration code |`, direction `{in | out | both}`).
- `state-machines.md`: `## {Entity}` per lifecycle entity, each with a Mermaid stateDiagram and `| From | To | Guard | Enforced at | Flow |`.
- `glossary.md`: `## Terms` with `| Term | Also called | Code identifier | Flows |`; `Also called` holds every alias found in code, curated docs and Notes, in whatever language it appears.
- `not-supported.md`: `## Not supported` with `- {statement} - {evidence: a hardcoded value, an explicit rejection, an absent branch, or a curated doc path}`.

### Ledger, playbook, contracts, debt, surfaces

Each has an H1, the sections named here, then `## Notes`.

- `ledger/rules.md`: `## Rules` with `| Id | Rule | Kind | Flows | Enforced at | Doc | Rationale | Confidence | Quirk | Last touched |`; `Kind` is `{code | process | policy | rollout gate}`; `Enforced at` is `file:line` for `code` and `process - <doc path>` otherwise; `Doc` is the curated `rules/` path or `none`; `Flows` for a non-code rule is the flows whose docs or cards name it, else `none - not tied to a flow`; `Last touched` is the author and date of the last commit to the enforcing lines, `n/a - process rule` otherwise. A non-code row enters the ledger only through the Link pass, from a `rules/` doc no card row matched. `unknown-rationale.md`: `## Unknown` with the same columns, only the rows whose confidence is `unknown`. `chains.md`: `## R-n` per rule holding the block `domain-rationale-chain` emits.
- `playbook/by-symptom.md`: `## Symptoms` with `| Symptom | Flows | First checks | Past incidents |`; `Past incidents` cites `incidents/` files by path, filled by the Link pass from every incident whose text names the symptom or a flow in the row.
- `contracts/<caller>.md`: `- **Kind:** {team | external system | ui app}`, `- **Doc:** {consumers/<name>.md | none - no consumer doc}`, then `## Surfaces used` with `| Surface | Flow | Sharp edges |`.
- `debt/register.md`: `## Register` with `| Id | Location | Signal | Severity | Category | Trade-off made | Cost today | Fix | Detection | Doc | Flows |`; `Signal` is the card Debt row's `class` and finding (`swallowed error: payments outage answered 202`), or for `hotspot`, `single point of knowledge`, and `coupling` the class and its numbers; `Severity` and `Category` per the card enums; `Doc` is `tech-debt/<file>.md#<anchor>` when a curated item names the same location, else `none`. `detection-gaps.md`: `## Gaps` with `| Flow | Priority | Signal | Monitor | Error tracker | Gap |`, `Signal` being `no signal` (Monitors `none` or `unknown`, and Error tracker `none` or reading `captures on this path: none`) or `capture only` (an error-tracker capture but no monitor); a `monitored` flow is never a row. `recent-risk.md`: `## Recent risk` with `| Flow | Commits ({window}d) | Monitor | Risk |`, one row per flow with 3 or more commits in the window.

### Indexes

`_index/file-to-flow.json`, keyed by root-relative path, rebuilt whole from the `files` list of every non-orphaned card; a key with no flows is omitted:

```json
{ "repos/orders/app/services/refund_service.rb": ["payments/order-refund"] }
```

`_index/sync-state.json`, the authoritative sync record, written by the Record pass; `version` is `2`, `synced` the date of the last completed `init` or `update` (an `import` Record keeps it), each repo's `path` its directory and `sha` the full `git rev-parse HEAD` at that sync (`synced` and `sha` are `null` until the first Record), `window` the day count both windows use, `fetch` whether the last run fetched, `in_progress` the `{command}:{pass}` a running command is in or `null`, `curated` the per-folder doc counts read at Finalise, one key per curated folder in the folder table's order (`specs` counting both `specs/` subfolders), zeros included:

```json
{
  "version": 2,
  "synced": "2026-09-26",
  "window": 30,
  "fetch": true,
  "in_progress": null,
  "curated": { "rules": 12, "specs": 1, "incidents": 3, "tech-debt": 0, "adr": 0, "consumers": 0, "patterns": 0, "context": 2 },
  "repos": {
    "orders": { "path": "repos/orders", "sha": "3f2a1c9e0b7d4c2a91f6e8d5b3a7c1e2f4d6a8b0", "branch": "main", "scope": "all", "stack": "Ruby / Rails 7.2", "database": "PostgreSQL", "surfaces": 42 }
  }
}
```

`scope` is the `## Repos` cell with its table escapes removed (`\|` becomes `|`). `_index/last-sync.md` is the full report block the last command emitted, written whole.

### Stale marking

The Mark pass diffs each repo from its recorded `sha` to the tip the run records, within the repo's scope. A changed file the reverse index maps marks every flow it maps to: the card's `freshness` becomes `stale` and a `## Changed since` section is inserted before `## Notes` (or extended when present) with `| Date | Commit | Files |`, one row per commit `git -C repos/<repo> log <sha>..<tip> -- <mapped files, repo-relative>` lists, ascending, `Commit` reading `<short sha> <subject>` and `Files` the root-relative mapped files that commit changed; a commit counts when it changes at least one in-scope file. The mark propagates to the capability's Flows `Status`, the ATLAS row, and the ATLAS counts line. A changed file the index does not map (files under a `test`, `tests`, `spec`, or `__tests__` directory, or named `*_test.*`, `*.test.*`, or `*.spec.*`, excepted) is one ATLAS `## Unmapped changes` row with the newest commit in the range touching it (root-relative `File`, `Commit` as a short sha, `Date`), replacing the `none` row; a row leaves when Discover places its file, the reverse index maps it, or the file is gone at the tip. A changed file that a curated doc cites is left to the Verify citations pass, which rewrites `## Citation drift`; the doc itself is never edited. Regenerating the card restores `current`, removes `## Changed since`, and refreshes line numbers. A `## Changed since` section on a stale card is not drift. The recorded `sha` advances only in the Record pass, so an interrupted `update` diffs from the same base next time.

## Output Format

Emitted by every sync command, inside its report, and by standalone verification.

```
- **Layout:** {created | updated | verified | drifted}
- **Root:** {absolute path}
- **Files:** {n} written, {n} verified, {n} seeded, {n} deleted, {n} curated read
- **Deleted:** {paths | none}
- **Drift:**                                              {only when any check failed}
  - {path} - {missing | missing folder | occupied by curated file | outside both layers | key missing: <key> | wrong-layer key: <key> | sections missing: <a>, <b> | index invalid | freshness mismatch: <file> vs <file> | state mismatch: <field> | id renamed: <old> -> <new> | curated missing frontmatter | curated status invalid: <value> | deprecated without superseded_by | generated path collides with curated folder: <folder>}
```

`created` is `init`; `updated` is `update` and `import`; `verified` and `drifted` are standalone results. `written` counts generated files, `_index/` included, created, regenerated, or marked; `seeded` counts the `seed` files created this run, an empty `.gitkeep` included; `deleted` counts the orphans `init` removed, each listed under `Deleted`; `verified` counts generated files, `_index/` included, read with no drift line (a file with one is not counted); `curated read` counts the Markdown files under the curated folders at the end of the run, files ingested this run included, each checked for frontmatter with `title`, `status`, `created`, `updated`, `tags` and a valid `status`. Every command runs these checks on the paths it reads (a path it did not read gets no drift line; scaffolding content and `repos/` are never checked) and lists under `Drift` the failures its own writes did not fix; standalone verification reads every path; standalone verification writes nothing, so `written`, `seeded`, and `deleted` are `0`, and the drift list is what the next `init` corrects. Drift lines follow layout-table order, one line per failed check. `missing` is a fixed generated path absent, a `surfaces/<repo>.md` absent for a repo `sync-state.json` lists, or a card or overview file an ATLAS row, a `Flows` cell, or `file-to-flow.json` names that is absent (a `capabilities/`, `contracts/`, or `surfaces/` file nothing names is not checked); `missing folder` is a curated folder or `_templates/` absent; `key missing` is a frontmatter key the layer requires absent (generated: `generated`, `id`, `freshness`, `synced`, `sources`, `aliases`, and on a card `capability`, `priority`, `ranked_by`, `verified_by_trace`, `files`; curated: `title`, `status`, `created`, `updated`, `tags`); `curated missing frontmatter` is a curated file with no frontmatter block; `curated status invalid` is a `status` outside its enum; `deprecated without superseded_by` is as named; `occupied by curated file` is a file without `generated: domain-sync` at a generated path below the root; `outside both layers` is a Markdown file outside `repos/`, `tmp/`, the dot-folders, the curated folders, the generated paths, and the scaffolding; `wrong-layer key` is `status` on a generated file or `freshness` on a curated one; `sections missing` names the sections a file's template lists that it lacks (an orphan's frozen body is exempt); `index invalid` is a JSON index that does not parse, names a flow that does not exist, names a file missing at the tip that no stale card lists, or omits a non-orphaned card's file, or an `index.md` `## Files` that omits a generated Markdown file it lists by rule; `freshness mismatch` is a card whose `freshness` differs from its capability Flows `Status` or its ATLAS row; `state mismatch`, attributed to `_index/sync-state.json`, is a field that disagrees with the files (`surfaces` against the inventory's real rows, `curated` against the folder counts); `id renamed` is a frontmatter `id` that differs from the path-derived id and is resolved by restoring the path-derived id and recording the other as an alias; `generated path collides with curated folder` is a generated file under `rules/`, `specs/`, `tech-debt/`, or any other seed folder.

## Avoid

- Treating `ATLAS.md` as the agent entry point or `index.md` as the human one
- Adding a `## Notes` section or frontmatter to the JSON indexes or `last-sync.md`
- Writing a flow reference in any form other than `<capability>/<flow>`
- Advancing a repo's recorded `sha` anywhere but the Record pass
- Writing, moving, or adopting a curated file from any sync pass other than through `domain-kb-ingest`
