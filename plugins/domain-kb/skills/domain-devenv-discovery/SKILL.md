# Domain Dev Environment Discovery

> Load `Use skill: stack-detect` first to determine the repo's stack, run once per repo with `repos/<repo>/` as the project root (never another repo's or the knowledge-base root's result), then `Use skill: domain-devenv-layout` (its Manifest section names every field an `Unknowns` line may cite, its naming contract the values) and `Use skill: domain-devenv-stack-profiles` (the per-stack evidence, defaults, and `Unknowns` entries this inventory checks).

Reads one service repository and states what it needs to run next to its peers: the runtime, the port, the processes, every piece of infrastructure it connects to and the config key it reads for it, the other repos it calls, the systems outside the domain it calls, and the values it cannot start without. Every value is cited; whatever the repo does not say stays `unknown`.

## When to Use

- `task-domain-devenv` `init` and `update`, once per repo under `repos/`
- Standalone: one repo directory named by the user; the inventory is emitted inline

## Inputs

| Input            | Required | Notes                                                                                                         |
| ---------------- | -------- | ------------------------------------------------------------------------------------------------------------- |
| Repo             | yes      | `repos/<repo>/`, read at its checkout `HEAD`                                                                    |
| Stack            | yes      | The `stack-detect` block for the repo                                                                         |
| Other repos      | yes      | The other directory names under `repos/`, to tell a peer from an external dependency                          |
| Surfaces         | no       | `surfaces/<repo>.md` when the knowledge base records a sync; its `outbound client`, `message`, and `event out` rows are where to look first, and its peers' `internal api` rows are the calls a stub needs |
| Scope            | no       | The repo's `scope` from `sync-state.json` when synced (`all`, or `include=<regex>` over repo-relative paths)       |

## Rules

- **Evidence or `unknown`.** Every value cites `repos/<repo>/file:line`, root-relative as the manifest and the surfaces files cite; a value the repo does not state is `unknown - <what is missing>` and also an `Unknowns` line. An `Unknowns` line names the manifest field a person sets, the repo change the environment cannot make, or the decision a person makes. A framework default counts only as the profile's `default`, never as evidence. Only what the development environment reads counts: a key, host, or setting read solely under a `production:` entry, a production profile, or a production config file is not a row. A call path code cannot pin may cite a runtime trace the caller supplies, as `(from <tool>)` in its Evidence cell. A second server, worker, or frontend entry point in the repo is an `Unknowns` line naming it (stack-detect's `fullstack` alone, a Next.js app with route handlers or an ORM, is not one); the block describes the entry point the repo's main manifest names.
- **Unreadable files are named, never worked around.** A file the session refuses to read (an env file behind a guard) is the `Unknowns` line `env files: not read (<paths>) - a person checks them`; a refused key or certificate file is instead a `Committed credentials` entry by path, its kind from its name (`private key (.pem)`); no other command, path spelling, or tool is tried for either. Development values also live outside dotenv files: environment-suffixed config files, dev-container env files, and a frontend's own config directory.
- **Scope.** With an `include=` scope, a row of any table whose every citing site lies outside it gets ` (out of scope)` after its first cell; the workflow leaves those out of the manifest.
- **Credentials are cited, never copied.** A committed live credential (a private key, a bot or API token outside a dev seed or example file) is a `Committed credentials` entry by `file:line` and kind; its value appears nowhere.
- **Existing container files are evidence, never templates.** A `Dockerfile`, compose file, `.devcontainer/`, `.env.example` or `.env.sample`, `Procfile`, CI service containers (`services:` in a GitHub Actions or GitLab job), and deploy configuration (ECS task definitions, Terraform, Helm values) are read for engine versions, packages, ports, processes, and env keys; their structure is not copied, and a Dockerfile's base tag is not a runtime source (the profile's files are).
- **A config key is the name the running service reads.** It is the env name the code or config file reads (`ENV.fetch("X")`, `ENV["X"]`, `<%= ENV[...] %>` and `${X}` in YAML, `process.env.X`, NestJS `ConfigService.get('X')`, `os.environ`, `os.getenv`, `os.Getenv`, viper `AutomaticEnv` with its `SetEnvPrefix`: a nested `a.b` is `PREFIX_A_B` only with `SetEnvKeyReplacer` mapping `.` to `_`, and only for a key viper already knows (a config-file entry, `SetDefault`, `BindEnv`) when the struct is read through `Unmarshal`; else no shell-settable key); a Spring property is its relaxed-binding env name: dots become `_`, dashes are removed, the rest upper-cased (`spring.datasource.url` is `SPRING_DATASOURCE_URL`, `app.log-startup-info` is `APP_LOGSTARTUPINFO`), unless its value is a `${X}` or `${X:default}` placeholder with an env-style `X`, which makes `X` the key; a `@Value("${a.b}")` naming a dotted property keys by that property's relaxed name. A NestJS `ConfigService.get('a.b')` on a namespaced config (`registerAs`, `load:`) keys by the `process.env.X` its factory reads. A key a library reads by convention with no code site (Rails `DATABASE_URL`, which merges over `config/database.yml` unless the environment's entry sets `url:`; `<NAME>_DATABASE_URL` per extra database; Sidekiq's `REDIS_URL`; django-environ's `env.db()` reading `DATABASE_URL`; a pydantic-settings field as `env_prefix` joined literally with the upper-cased field name, a nested path joined by `env_nested_delimiter` (`APP_DB__HOST`; a sub-model is also settable as JSON in its parent's env var), a field with `validation_alias` or `alias` keyed by the alias alone, no prefix; dynaconf as `<PREFIX>_A__B`) is cited at the file that activates the convention (`config/database.yml`, the initializer, the settings class). Any other settings library is keyed by its own documented env mapping, cited at the library's config; a settings value templated from the env is a key too; with the library's env mapping off, the setting has no env path. A setting the code fixes with no env path is not a key: it is `hardcoded at file:line` under `Unknowns`, a repo change the environment cannot make.
- **Infra is what the code connects to.** A driver or client in the package manifest is a candidate; the config key that feeds it, cited where it is read, makes it a row. Engines: `mysql`, `postgres`, `redis`, `rabbitmq`, `kafka`, `keycloak` (any OIDC issuer, JWKS, or Keycloak admin URL), `mailpit` (SMTP settings), `sqlite` (embedded; a `Uses` row that needs no infra entry). Object storage, a cloud queue, or a search engine is an `External` row (`<what>`), its `Port` by the External rule below; a datastore outside the engine list (MongoDB, Memcached, Cassandra) is the `Unknowns` line `uses.<engine>: no profile for <engine> - a person adds it in compose.local.yaml`, never an `External` row. When one engine is configured through several keys, each key is a row with its `Role`; the `Dev value` cell carries the value the repo's development config or example file gives the key, whole (a `url` with its scheme and driver prefix; a `database`, `db`, `client id`, or `vhost` as named), else the code default at the read site marked ` (code default)`, else `-`; the same holds in every table's value cell. A name the development config or code fixes with no env path (a database name, a Keycloak host or realm, a queue or topic name) is a row with Config key `(hardcoded)` and its Role, its value in `Dev value`: the workflow adopts it rather than reporting it; a hardcoded connection host or port is the `hardcoded at file:line` repo-change unknown. A schema or migration that sets a `DEFINER` is noted on the `Migrate` line (`definer - file:line`). A credential the naming contract fixes (a database password, a Keycloak client secret) is a `Uses` row by its `Role`, never a `Secret`; `Secrets` are credentials for systems the environment does not provide. Credentials an install step reads (a private package registry token, a dependency fetched over SSH) are `Build` `secrets` and `ssh`, never runtime `Secrets`; a private gem source host gives Bundler's env name `BUNDLE_<HOST>` (host upper-cased, `.` as `__`, `-` as `___`: `BUNDLE_GEMS__EXAMPLE__COM`).
- **A peer is another repo in this domain.** An outbound base URL key is a peer when its development or test default names another repo's host or service, its key or client name starts with another repo's name, or a surfaces row of that repo serves the paths it calls. Otherwise it is external, and when its host is a dev host no repo evidence resolves, an `Unknowns` line names the candidate repos for the consuming workflow to re-file against their `Dev hosts`. A peer row lists the calls found (`METHOD /path`, a path parameter written `{id}`), which seed its stubs; calls made through a client package the repos do not contain are matched by method name against the peer's routes or surfaces rows and suffixed ` (matched, unconfirmed)`; a configured key with no call site is a row with `Calls` `none - no call site`. An external row lists its calls too: for object storage or a cloud queue the SDK operations used (`PutObject`, `SendMessage`), which seed its stubs; `none - not HTTP` only for a protocol that is not HTTP, and its `Port` is the port of the URL named by, in order, the production config, the code default, then the dev value (`443` for a bare `https://`, and for an SDK-addressed service with no URL), else `unknown`; one system is one row across repos, matched by host, not by label. A call development already short-circuits reads `Calls` `none - mocked in-process at file:line` or `none - gated by <flag> at file:line`, which seeds no stub. A cloud SDK that reads a standard endpoint-override env in the locked SDK version (AWS `AWS_ENDPOINT_URL` or `AWS_ENDPOINT_URL_<SERVICE>`) makes that env the row's key, with the region key the SDK then needs as an `Env` row and each static-credential key an `Env` row when the repo gives a dev value, else a `Secret`; path-style addressing the SDK only takes in code is an unknown.
- **Key markers.** A key gets one suffix when it applies: ` (browser)` - a browser loads the value (a `NEXT_PUBLIC_*` or `VITE_*` key, a redirect target, a script or beacon host, a presigned URL), so it needs a proxied origin and never an `http://*.mock` one; ` (credential)` - the caller's credential for a peer (client id or secret, API key); ` (host only)` - the client takes a bare host and adds the scheme and port itself; ` (self origin)`, ` (self host)`, ` (self port)` - an `Env` key holding the service's own public origin, host, or port, used to build absolute URLs. A `SCHEME` and `HOST` pair is two rows of one peer or external, the scheme row's Dev value `http` or `https`. A non-address value an external needs (a sandbox client id, a region, a fingerprint) is an `Env` row when the repo gives a dev value, a `Secret` when it is a credential with none; only an address (a bucket, queue, or resource name) stays on the `External` row, as its `Dev value`.
- **Versions.** The runtime from the files the profile names. An engine's version from deploy configuration (the production source), then CI service containers, then an existing compose file, cited; a version is exact in the engine's full release form (PostgreSQL `major.minor`, `16.4`; MySQL, Redis, RabbitMQ, Kafka, Keycloak `x.y.z`), from a tag or a managed-service `engine_version` alike (RDS `"8.0.39"` is exact); a floating tag (`mysql:8.0`, `redis:7`), a partial `engine_version` (ElastiCache `7.1`), or an Aurora composite (`8.0.mysql_aurora.3.x`) is not a version and the search moves to the next source, `unknown - floating tag <tag>` when nothing exact follows; one found nowhere `unknown - no production version in the repo`; a Keycloak tag below 26 `unknown - Keycloak below 26`; a Kafka version below 3.7.0 `unknown - Kafka below 3.7 (apache/kafka image floor)`; a kafka image other than `apache/kafka` `unknown - kafka image <image>` (a Confluent tag is not a Kafka version); tool images (`mailpit`, `wiremock`, `proxy`, `playwright`, `curl`) get no `Engine` row, the consuming workflow pins them; the `Version` cell is the bare version, a tag's `-management` or `-alpine` suffix dropped. Two repos naming different versions of one engine is the consuming workflow's decision, not this repo's.
- **Dev hosts and HTTPS are read from the repo, certificates are not.** A dev host is a name the repo's own development setup serves or expects (a `.devcontainer` or compose hostname, a documented hosts-file entry, `config.hosts`, an app URL or OIDC redirect URI in development config, a cookie domain), marked `route` or `keycloak` by what it serves, or `mock` when the repo's dev container serves it itself (a stand-in page or session service, never the app): a `mock` host is never a route and tells the workflow which external a browser reaches; `localhost` is never one. Routes the app scopes to a host (a host constraint, subdomain routing) are the `Route hosts` line: a peer calling `<svc>:<port>` would miss them. A header an edge gateway injects and the app trusts (a user id read from a request header) is the `Edge headers` line, with the source the dev container's gateway config derives it from. HTTPS is required when development code demands it (`force_ssl`, `Secure` or `SameSite=None` cookies, `https://` redirect URIs, HSTS, a peer called by an `https://` URL). A certificate or key file in the repo is read only for the host names it covers, which are dev-host evidence; its key material is never used. TLS is on in every environment by default, so the HTTPS line decides nothing by itself: it explains the hosts and feeds the scheme check. Where the profile's `Scheme` slot says `set in code`, that setting is looked for; absent while the code builds absolute URLs from the request (redirects, OAuth callbacks, mail links), it is an unknown; absolute URLs built only from a configured origin key (a ` (self origin)` `Env` row) need no forwarded scheme, and `Proxy scheme` reads `not needed`. A service that terminates TLS itself in development (`server.ssl.*`, puma `ssl_bind`, uvicorn `--ssl-*`) is an unknown unless its profile's web command replaces the configured binds (the profile says so): the proxy terminates TLS. Forcing HTTPS in development (`force_ssl`, `requiresSecure`, `redirectToHttps`) is an `HTTPS` reason, not an unknown: the probe sends the forwarded scheme and peers call the service at its origin. A `config.hosts =` assignment in `development.rb` replaces Rails' host list and is an unknown, as is each `Unknowns` entry the service's profile names, by the profile's own predicate (Django `ALLOWED_HOSTS` not read from env, a Flask or FastAPI trusted-host setting, Next.js `allowedDevOrigins` or Vite `server.allowedHosts` absent, Yarn Plug'n'Play, a Prisma `output` inside the source tree, a Rails `config.file_watcher = ActiveSupport::EventedFileUpdateChecker`).
- **Kind.** `backend` serves HTTP; `frontend` is a browser app; `worker` has no listener (a consumer or scheduler only). A library, a schema or contract package, an infrastructure-as-code repo, or a repo with no server, worker, or frontend entry point is `Kind: not a service` with the evidence, and the block ends there.
- **Profile checks run here.** A profile line conditioned on repo evidence (a gem, a Procfile line, a routed path, a credentials file, a lockfile) is checked by this skill and recorded in the block (`Packages`, the Process table, `Health`, `Secret` rows, `Build`), which the workflow writes into the manifest's `packages`, `processes`, `health`, `secrets`, and `build`; rendering reads those fields and never re-applies the condition.

## Patterns

### Where to look first

| Slot          | Look in, in order                                                                                                              |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Processes     | `Procfile`, `Procfile.dev`, `package.json` scripts, `Makefile` run targets, the profile's worker gems or libraries, an existing compose file's services; a process that listens (a dev asset server the pages load from) gets its `Port` and the paths the pages request from it |
| Port          | the server config (`config/puma.rb`, `server.port`, the `listen` call, `uvicorn` arguments), `PORT` default, then the profile default |
| Infra keys    | `config/database.yml`, `config/*.yml`, `config/initializers/`, `application*.yml` and `.properties`, `settings.py`, a config module, `.env.example` |
| Peers, external | client classes and their base-URL config, `surfaces/<repo>.md` outbound client rows, HTTP client construction sites          |
| Secrets       | keys read with no default whose name or use is a credential (`*_KEY`, `*_SECRET`, `*_TOKEN`, `*_PASSWORD`, Rails credentials), `.env.example` entries left blank, minus the `Uses` credentials |
| Roles         | authorization checks on a token role (`@PreAuthorize("hasRole(...)")`, `@Roles`, a claims lookup); a scope check (`hasAuthority('SCOPE_x')`) is an `Unknowns` line (`uses.keycloak.roles: client scope x - add it to the realm by hand`); a database-backed role check (`rolify` `has_role?`, the app's own roles table) is an `Unknowns` line (`uses.keycloak.roles: roles live in the database - seed them`) |
| Topology      | rabbitmq only: exchange, queue, and binding declarations in code (`apps`); none in code and present in deploy configuration (`provisioned`, each declaration listed) |
| Browser       | for a frontend: the API base URL key and every outbound call's host; for a backend: `from the frontends' inventories` (the consuming workflow fills it) |
| Seeds         | development seed files: a fixed dev client they create for callers (`Dev clients`); an outbound URL kept in a database row rather than config (a webhook target, a client callback) is the `Unknowns` line `db-stored: <what> at file:line - add a task in devenv.yaml` |
| Dev hosts, HTTPS | the dev container's gateway or web-server config (hosts, injected headers, mock sites), `.devcontainer/`, compose files, README setup steps, `config/environments/development.rb`, session and cookie config, OIDC client config, `server.ssl.*`, certificate files' subject names |
| Build         | the facts the profile's Dockerfile and commands need, for the manifest `build` map: `tool` (bundler, gradle or maven, npm or pnpm or yarn by lockfile - `yarn1` when `yarn.lock` contains `# yarn lockfile v1` - uv or poetry or pip by lockfile, go; a lockfile no profile tool owns, `bun.lock`, `bun.lockb`, `pdm.lock`, is `unknown - no profile tool`; a `package.json` with no lockfile is `unknown - no lockfile`), `framework` (node: nest, tsx, node by the dev script; python: fastapi, django, flask; web: next or vite by that dependency, else unknown), `bundler` (web with next: `webpack` when the dev script carries `--webpack` or Next.js is below 16, else `turbopack`), `entry` (node: the dev script's entry file; python: `<module>:<app>` from the uvicorn or gunicorn `UvicornWorker` call, or from the file a `fastapi run` names converted to its dotted module and the `FastAPI()` variable it assigns (`app/main.py` -> `app.main:app`), or `<module>` from the Flask app), `debugger` (rails: `rdbg` when `debug` is in `Gemfile.lock`, else none), `generate` (node: `prisma` when a schema exists, else none), `native` (node: true when the lockfile marks an install script - `"hasInstallScript": true` in `package-lock.json`, `requiresBuild: true` in a pnpm 8 or earlier lockfile - false when such a lockfile has no marker, `unknown - no install-script marker in <lockfile>` for a pnpm 9 or later or a yarn lockfile), `manifests` (the optional files the profile names that exist: `.npmrc`, `pnpm-workspace.yaml`, `.yarnrc.yml`, `.yarn/`, `prisma/`, `prisma.config.ts`, a dev requirements file, Rails `package.json` and lockfile; `.` for a workspace monorepo or a `gemspec`/`path:` Gemfile), `steps` (the builds the profile names that the repo has a script for: node `npm run build`; rails `<install> && npm run build`, `<install> && npm run build:css` - `<install>` the node profile's install for the repo's JS lockfile (`npm ci`; `yarn` or `yarn1` and `pnpm` through corepack), the `yarn` script forms with `yarn.lock` - or `bin/rails tailwindcss:build`; web none, its profile runs the dev server in both modes), `secrets` (the env names an install reads a private registry credential from - a lockfile source host, a registry config `${TOKEN}`), `ssh` (true when a dependency is fetched over `git@` or `ssh://`), `node` (rails with a `js` or `css` line: the `.node-version` or `.nvmrc` pin), `framework_version` (rails: the `rails` version in `Gemfile.lock`); node writes `processes.web: exec npm run start:prod` when that script exists; a process whose live command differs is written `{run: <cmd>, live: <cmd>}`, a live-only one `{live: <cmd>}` |
| Profile fields, Health | spring: the boot module from `settings.gradle*` or the parent `pom.xml` and the `bootJar` or `spring-boot-maven-plugin` module (`module`), and `management.server.port`, which turns `Health` into `tcp`; any stack: a health endpoint mounted as middleware ahead of host checks wins over a routed one; go: `main` always (`./cmd/<svc>`, else the only `./cmd/*`, else `.` for a root `main.go`; several and none is `<svc>` is `unknown - several main packages`), and the CLIs the profile installs (`tools`, each at the version a Makefile `go install <module>@v<x>` names, or, for a go.mod `tool` directive (which names only the package), the `require` line of the module that provides it, else `unknown - pin a version` and an `Unknowns` line `tools.<cli>: no version in the repo - set it in devenv.yaml`); unknown profile: `base`, `build.install`, `web` |
| SAML          | the app's SAML service-provider config: the SP entity id and the assertion consumer URL (paths or origin-relative), the IdP certificate or fingerprint setting, and the file or env that gives its effective development value |

Bad - a guess presented as a fact, and a peer mistaken for an external system:

```
| mysql | DB_HOST | host | - | (Rails default) |
| payments | PAYMENTS_URL | - | 443 | POST /payments/refunds | repos/orders/app/clients/payments_client.rb:8 |
```

Good - the key the code reads, and the peer recognised by its default host:

```
| mysql | DATABASE_URL | url | mysql2://root@127.0.0.1:3306/orders_development | repos/orders/config/database.yml:14 |
| payments | PAYMENTS_URL | http://payments:3000 | POST /payments/refunds, GET /payments/refunds/{id} | repos/orders/app/clients/payments_client.rb:8, repos/orders/config/settings.yml:22 |
```

## Output Format

One block per repo, every table kept with its header and one `none - <evidence>` row when empty (a `not a service` block ends after its `Kind` line):

```markdown
### {repo}

- **Stack:** {Language} / {Framework}{ {framework version}} ({{language runtime version} - {file:line} | unknown - <what is missing>})
- **Profile:** {rails | spring | node | python | go | web | none - not a service | unknown - no profile for <Framework>}
- **Kind:** {backend | frontend | worker | not a service - <evidence>}
- **Port:** {n - file:line | n - profile default | none - worker | unknown - <what is missing>}
- **Health:** {path - file:line | tcp | none - worker | unknown - <what is missing>}
- **Migrate:** {command - file:line | default | none - <evidence> | unknown - <what is missing>}{; definer - file:line}
- **Packages:** {package (because <dependency> - file:line), ... | none}
- **Build:** {tool: <x> - file:line; framework: <x> - file:line; entry: <x> - file:line; debugger: <x> - file:line; generate: <x> - file:line; native: <bool> - file:line; bundler: <x> - file:line; manifests: <paths> | none; steps: <commands> - file:line | none; secrets: <ENV>, ... - file:line; ssh: true - file:line; node: <version> - file:line; framework_version: <version> - file:line} {only the keys the profile reads, and secrets and ssh when found}
- **Profile fields:** {module: <module> - file:line; main: <package> - file:line; tools: {<cli>: <version to pin>, ...}; base, build.install, web - set by hand (profile custom) | none}

| Process | Command | Port | Evidence |
| ------- | ------- | ---- | -------- |

| Uses | Config key | Role | Dev value | Evidence |
| ---- | ---------- | ---- | --------- | -------- |

| Peer | Config key | Dev value | Calls | Evidence |
| ---- | ---------- | --------- | ----- | -------- |

| External | Config key | Dev value | Port | Calls | Evidence |
| -------- | ---------- | --------- | ---- | ----- | -------- |

| Env | Dev value | Evidence |
| --- | --------- | -------- |

| Secret | Evidence |
| ------ | -------- |

| Engine | Version | Evidence |
| ------ | ------- | -------- |

- **Roles:** {role, ... - file:line | none}
- **Topology:** {apps - file:line | provisioned - exchange <name> <type>; queue <name>; binding <exchange> -> <queue> <routing key> - file:line | none in this repo - <where looked> | none - no rabbitmq}
- **Browser:** {API base key <KEY> = <development value> - file:line | from the frontends' inventories | none - no API calls}
- **Dev hosts:** {host (route | keycloak | mock) - file:line, ... | none}
- **Route hosts:** {constrained to <host>, ... - file:line | any}
- **Edge headers:** {<Header> from cookie <name> - file:line, ... | <Header> from <other source> - file:line | none}
- **SAML:** {entity id <path> - file:line; acs <path> - file:line; IdP certificate pinned at <file:line or KEY>, effective value from <file:line> | none}
- **Dev clients:** {<client id> / <secret> for <caller | any caller> - file:line, ... | none}
- **Committed credentials:** {<kind> at file:line, ... | none}
- **HTTPS:** {required - <reason> file:line; ... | not required}
- **Proxy scheme:** {KEY=value | trusted by default | not needed | set in code - file:line | not set - no absolute URLs built | unknown - <setting> absent, absolute URLs built at file:line}
- **Unknowns:**
  - {slot}: {why} - {set `{manifest field}` in devenv.yaml | repo change: <what> | <what a person decides>}
  - env files: not read ({paths}) - a person checks them     {when a guard refused one}
```

`Process` names are `web` and each other name as the `Procfile` or script calls it, `release` excepted; `Command` is `default` when the profile's command applies; `Port` is `-` for a process that does not listen, else `<port> (<path>, ...)` with the paths the pages request from it. `Role` is `{url | base url | host | port | user | password | database | db | issuer | realm | client id | client secret | vhost | bootstrap servers | smtp host | other}`; `issuer` only for a value used as the issuer as-is, `base url` for a Keycloak origin the client appends `/realms/<realm>` to. `{slot}` in an `Unknowns` line is the manifest field path it is about (`port`, `env.APP_HOST`, `uses.keycloak.roles`), else a short label (`config.hosts`, `db-stored`), so the workflow can retire it. `Calls` reads `none - <evidence>` when no path is found. `Dev value` in the Peer and External tables is the key's development or example value, whole (a URL, an ARN, a queue name), else its code default marked ` (code default)`, `-` when the repo gives none. `Env` lists only keys the service needs to boot that no other table covers, with the value the repo's own development config or example file gives. `Unknowns` reads `- none` when every slot is cited.

## Avoid

- Copying an existing Dockerfile or compose file instead of mining it for facts, or proposing a repo's certificate or key for reuse
- Reporting a library the package manifest declares but no code configures as infrastructure
- Filling a version, port, or key from what the framework usually uses
- Retrying a file a guard refused through another command, spelling, or tool, or quoting a committed credential's value
