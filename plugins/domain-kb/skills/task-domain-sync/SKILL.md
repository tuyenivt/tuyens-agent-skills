# Domain Sync

Builds the generated layer `domain-kb-layout` defines from the service repositories under `repos/`, refreshes it from the commits since the last run, seeds the curated layer, and imports facts or whole documents into it through `domain-kb-ingest`. Runs at the knowledge-base project root, writes files as each pass completes, and never commits.

## When to Use

- No command (`update`): a synced root after new commits in any repo, or after a repo was added under `repos/`
- `init`: a root with repos under `repos/`, built from scratch; on a synced root (layout drifted, contract changed, a fresh start wanted) it regenerates every generated file, keeping `## Notes`, the carried `CLAUDE.md` sections, aliases and ids, and `_index/priority.json` until its Rank pass rewrites it, and deletes the orphans whose `## Notes` is empty; a populated curated layer is left untouched
- `import`: a fact, a file, or a whole foreign knowledge base to place into the curated layer; needs no prior sync

**Not for:** reading the knowledge base (`task-domain-explain`), answering from it (`task-domain-ask`), or turning a ticket into a plan (`task-domain-solve`).

## Inputs

| Input            | Required | Notes                                                                                                                                       |
| ---------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Command          | no       | `init` or `import`; with no command the run is an `update`, or an `init` when `_index/sync-state.json` is absent or records no `sha`         |
| Window           | no       | Days for recent changes, ranking, and runtime corroboration; default `window` in `_index/sync-state.json`, else 30; recorded at the end       |
| Notes            | no       | Text the user pastes for a named flow, rule, or capability; appended to that file's `## Notes` once the file exists in this run               |
| `--repos <csv>`  | no       | Only these repos are fetched, marked, discovered, traced, and distilled; the others keep their recorded state and their cards               |
| `--since <ref \| date>` | no | Per repo, the base of the Mark and Distil range; a ref resolves against the tracked branch, an ISO date to `git -C repos/<repo> rev-list -1 --first-parent --before="<date> 23:59:59" HEAD` (prints nothing when no first-parent commit predates the date: the base is then `none`, as the Step 2 fallback says); default the recorded `sha` |
| `--no-fetch`     | no       | Skip Step 4; ranges are computed against the checkout as found                                                                              |
| `--capabilities <csv>` | no | Trace only triggers assigned to these capabilities; the rest stay `stale` or `missing` for a later run                                                 |
| `--max-flows <n>` | no      | Trace at most `n` cards in Step 7 order, then stop; the remaining stale cards stay `stale` and the remaining triggers `missing` for the next run |
| `--resume`       | no       | Continue the run `in_progress` records at its pass, with the interrupted command's flags and Window retyped alongside (flags are not persisted; Notes already appended are not retyped); given only when no other sync is running on this root |
| Text or `--in <path>` | `import` | Inline text, a file, or a directory to ingest; a directory is walked per Step 8                                                       |

## Workflow

Steps name the commands that run them; a command skips the others. Every command but an `import` on an unsynced root sets `in_progress` to `{command}:{pass}` in `sync-state.json` at the start of each pass after Step 2 it runs, per the layout, with the layout's pass names (Step 8 is `Distil`; an `import` sets `import:Scaffold` even when nothing is seeded; a pass `--no-fetch` skips writes none, a pass every repo skips for its own reason is still entered; a resumed run writes the pass it continues at); `--max-flows` ends Step 7, never the run; an interrupted `import` is not resumed, since its input is not persisted: `--resume` clears an `import:*` value (the one write Step 2 makes) and stops with `import interrupted - re-run import`. `import` runs Steps 1, 2, 3, 8, and, on a synced root, 11 to 14; on a root with no recorded `sha` it stops after Step 8 with its report emitted and nothing else written.

Use skill: `behavioral-principles`.

### Step 2 - Preflight

Use skill: `domain-kb-layout` for every path, section, and empty form named below; read its Rules and the Patterns sections Layout and write modes, Curated layer, Templates, Sync passes, Ids and references, Generated-file frontmatter, CLAUDE.md, index.md, ATLAS.md, Flow card, capability.md, Overview files, Ledger, playbook, contracts, debt, surfaces, Indexes, Stale marking, and its Output Format. Read only; nothing is written until every row passes, except the `import:*` clear below. With `--resume` the `in_progress` row is read first (a `null` value or an absent `sync-state.json` stops there), and the recorded command, not the typed one, selects the rows below and the rest of this step; the Command gate is skipped. `import` checks only the writable root, generated-path occupancy, command gate, and `in_progress` rows.

| `in_progress` in `sync-state.json`                             | null; with `--resume`, `{command}:{pass}`                  | set without `--resume`: stop with `sync in progress at {command}:{pass}, pass started {sync-state.json modified time, read before any write} - if no sync is running on this root, run task-domain-sync --resume with that command's flags`, since a running sync and a second one would write the same files; past Step 5 the tip of each repo in the run's repo set is the `HEAD` the interrupted run used, read from the reflog as the newest entry at or before the pass start time `T`, the `sync-state.json` modified time in unix seconds (`git -C repos/<repo> reflog show --date=unix HEAD`, the first line whose `HEAD@{<unix>}` is not after `T`, its sha resolved with `git -C repos/<repo> rev-parse <sha>`; `HEAD` as found when the reflog is empty, with the warning `<repo>: reflog empty - moved checkout not detectable`), and a checkout whose `HEAD` differs from it stops, one line per such repo, with `checkout moved since the interrupted run (<old> -> <new>) - restore it (git -C repos/<repo> checkout --detach <old>), then task-domain-sync --resume with that command's flags; or set in_progress null to abandon the run, then run task-domain-sync <command>` (`<command>` bare for `update`), since the commits between the two tips were never marked; a reflog whose every entry is after `T` counts as moved with `<old>` unknown, its stop line keeping only the abandon remedy (`checkout moved since the interrupted run (<old> unknown -> <new>) - set in_progress null to abandon the run, then run task-domain-sync <command>`); at or before Step 5 each checkout's `HEAD` as found is its tip; `--resume` with it null or the file absent: stop with `nothing to resume - no sync in progress` |

`import` skips the rest of this step. Use skill: `stack-detect` for its marker-file table, Refinements, and Stack Type classification (a repo's own instruction file (`CLAUDE.md`, `.claude/CLAUDE.md`, `AGENTS.md`, `GEMINI.md`) `## Tech Stack`, as that skill says), and apply them to each `repos/<repo>/` directory in turn, keeping each repo's `Stack Type` in memory for the repo order of Steps 6 and 7; its single-root detection and conversation cache are not used, since the knowledge-base root has no stack of its own. `Language` and `Framework` form the repo's stack note, `Database` its database, `unknown` accepted; they are derived on `init` and for a `new` repo, and on `update` the recorded values are kept. Read each repo's tracing initialisation for `Tracing:` and its error-tracker initialisation for `Errors:`, plus the service names both declare; an existing `CLAUDE.md` `## Observability` wins when present. Read each repo's `Scope` from `CLAUDE.md` `## Repos` (`all` when absent); `--repos` narrows the repo set for Steps 4 to 8. A repo with no recorded `sha` on `update` is `new`: it is discovered and traced in full, not marked or distilled, and recorded at the end. These in-run values feed every later step; the `stack-detect` block itself is never emitted.

On any stop the workflow emits the `Setup required` block with the commands in order, reading a URL from `.gitmodules` when it has one and leaving `<url>` otherwise, and stops; a stop whose remedy is a `task-domain-sync` invocation, a `git checkout --detach`, or an edit names it in the line and its fence reads `none - the fix is named above`. It runs no git write to fix a preflight failure.

### Step 3 - Scaffold (`init`; `import` seeds `_templates/` only)

Per the layout's Scaffold pass: absent root files with header-only tables (an existing one is regenerated in Step 13 with its carried sections), `overview/` stubs, and, for an absent `CLAUDE.md`, `## Repos` rows in directory-name order with the repos whose `Stack Type` is `frontend` or `fullstack` last (the order Steps 6 and 7 then follow), `## Observability` from Step 2, the `Branch` and `Scope` cells, and the fixed `## Audience`, `## Solve`, and `## Precedence` text; `sync-state.json` per the layout's Scaffold pass: every field its Indexes section lists, `synced`, every recorded `sha`, `surfaces`, and `curated` kept (`null`, `0`, or zeros where none is recorded), `version` `2`, every repo's `path`, stack note, database, branch, and scope, the run's `window`, `fetch` `false`, `in_progress` `init:Scaffold`. Every `seed` path that is absent is created; a `seed` path that exists is not read or touched.

### Step 4 - Fetch (`init`, `update`; skipped by `--no-fetch` or for a repo with no `origin`)

Per repo, with `BRANCH` from Step 2:

```
git -C repos/<repo> fetch --quiet origin "+refs/heads/${BRANCH}:refs/remotes/origin/${BRANCH}"
```

The braces are mandatory: in zsh a bare `$BRANCH` followed by `:` and a letter is read as a parameter modifier. Then the guarded bump, only after a successful fetch: skip when Step 2 recorded the checkout dirty, ahead, diverged, on another branch, or detached off the tracked branch's history (reported `skipped (detached off <branch>)`); `git -C repos/<repo> checkout --detach origin/${BRANCH}` when detached; `git -C repos/<repo> merge --ff-only origin/${BRANCH}` when on the tracked branch, a refused merge (the remote was rewritten or diverged since Step 2) leaving the checkout as found and reported `skipped (ff failed)`. After a bump, for a repo `.gitmodules` lists, `git add repos/<repo>` in the root so the gitlink survives `git submodule update`; a plain clone has no gitlink and nothing is staged. A failed fetch warns and leaves the checkout as found. The tip the run records for each repo is its checkout `HEAD` after this step; Mark and Distil run from the base to that tip, Rank and Recent changes over the window ending today.

### Step 5 - Mark (`update`)

Per the layout's Stale marking, within each repo's scope: rebuild `_index/file-to-flow.json` from the `files` list of every non-orphaned card (so a card an interrupted run wrote is reached), diff each recorded repo from its base (`sha`, `--since`, or the Step 2 fallback) to the tip, mark every card a changed mapped file reaches, propagate to capability and ATLAS, append unmapped files to ATLAS `## Unmapped changes`. Changed files a curated doc cites are left to Step 12. Files out of scope are counted, not marked. A recorded repo whose directory is gone is not diffed; Step 6 orphans it.

### Step 6 - Discover (`init`, `update`)

Read every existing inventory's rows first, for the `new` and `gone` counts. Use skill: `domain-surface-discovery` once per repo in the run's repo set, in `## Repos` order with the repos whose `Stack Type` is `frontend` or `fullstack` last, passing the repo with its Step 2 stack note, its scope, the other repos with the inventories already written this run, the existing inventory, the capability table, and this repo's unmapped rows. Write each `surfaces/<repo>.md` whose files or rows changed; each trigger row carries its capability, which is the Discover set every later step and any resume reads. When `CLAUDE.md` `## Capabilities` has no rows at the start of the run and the run's repo set is every repo under `repos/`, write it from every repo's proposals after the last repo (under `--repos` it stays empty for a full run to fill). Remove each ATLAS `## Unmapped changes` row the atomic reports under `Placed`. Collect every `External callers named` entry for Step 11 and every `moves card:` entry for Step 7; on a run resumed past this step, `moves card:` holds each card whose frontmatter `capability` differs from its trigger row's `Capability` and whose id has no card under the row's capability (one whose id has a card there was traced before the interruption, and Step 13 deletes its old file), and `Consumers without a doc` reads `unknown - resumed at {pass}`. A card whose trigger lives in a repo discovered this run is marked `orphaned` when the layout's Ids rule matches it to no discovered trigger; an orphaned card whose trigger is discovered again keeps its frozen body and `orphaned` until Step 7 re-traces it with the stale cards. An inventory whose repo directory is gone is marked `orphaned`, with every card whose trigger lives in that repo; an orphaned card's files leave `file-to-flow.json` in Step 7.

### Step 7 - Trace (`init`, `update`)

A card is due for every trigger row of kind `ui screen`, `public api`, or `schedule`, and every `webhook in` or `message` row no card crosses as a hop, whose capability is not `infrastructure`; an `internal api` row, a crossed `message`, and a crossed `webhook in` (the callback that completes a hop its card started) are hops inside that card and never `missing`. `init`, and a `new` repo, trace every due `ui screen`, `public api`, and `schedule` trigger first, repo by repo in the Step 6 order, each inventory in its row order, then every `webhook in` and `message` row, across all repos, that no card written this run or earlier crosses; `update` traces every stale card (a rediscovered orphan included, passed as its id with the rediscovered row's surface), every card Step 6 collected under `moves card:` whatever its freshness (traced under its new capability with its id, `aliases`, and `## Notes` carried), and every due trigger with no card (`missing`): stale cards first by their `_index/priority.json` priority, the ones it does not list after them in the `init` order above, then moved cards (a card both stale and moved is traced here), then missing ones (a `new` repo's among them) in the `init` order above. `--capabilities` limits the set and `--max-flows` ends it, the run continuing with the next step the command runs; every due trigger left without a card is an ATLAS `### Untraced` row. Use skill: `domain-flow-trace` per card, passing the row's surface (or the stale card's id) as Trigger, the row's capability, every repo with its stack note, the KB root with both layers, the inventories, the Window, the `## Observability` values, and the Audience languages; then, on the card as traced (the atomic's "written card" is this text; the file is written once, after corroboration), when Step 2 found a tool reachable and the card's `Hops` is not `0` (a card with no backend route keeps the atomic's `unavailable - no backend route` lines and gets no call), Use skill: `domain-runtime-evidence` once per card with the `## Observability` service that serves the card's trigger surface (for a ui screen, the card's hop 1 under the `Services:` name the hop-1 repo's tracing initialisation sets), that surface, the card's Edge branches rows each with its guard and the log message string or exception name the guard emits, read at the row's `Enforced at`, `Tracing` and `Errors` as `## Observability` records them (the atomic writes the Step 2 reason into the blocks an unreachable tool sources), and the Window (for a ui screen the surface passed is that hop-1 route, never the screen path); then Use skill: `domain-flow-trace` in corroborate mode with the card as traced and the blocks, folding the fields it emits into the card, a `no monitor` Debt row it removes included; when no tool is reachable, every Runtime line reads `unavailable - <the Step 2 Tracing reason>` (a card with no backend route keeps `unavailable - no backend route`); the Error tracker line, derived from code, is never overwritten. Each card is then written whole, once (a `regenerate` write). Rebuild `_index/file-to-flow.json` from the `files` list of every card in the card set after the last card: the card set is every non-orphaned card but the old file of a moved card Step 13 deletes (one traced under its new capability this run, or found already traced there); an untraced moved card keeps its old file in the set; Steps 9 to 11 read it. Pasted Notes for a flow are appended here.

### Step 8 - Distil and ingest (`update`, `import`)

Every write to the curated layer in this step is one call per input of Use skill: `domain-kb-ingest`; no write outside an ingest call (a script, a shell loop, a copy) touches a curated file, and each call's `## Signal check`, `## Files`, and `## Conflicts` go into the report. Languages come from `CLAUDE.md` `## Audience` (`en` when absent).

**Distil (`update`).** For the commits in each recorded repo's range touching in-scope files, read messages and diffs and produce candidate facts: one sentence each in the first Audience language with the citation `repos/<repo>/<path>:<line> (commit <short sha>{, <ticket id>})`, the line being where the fact sits at the tip. Keep contract, behaviour, threshold, data-shape, failure-mode, flow, and decision changes, a code comment that states one included, whether or not code changed with it; drop tests-only changes, comments that only point or restate, renames, formatting, dependency bumps with no behaviour change, and log tweaks; rationale comes only from commit or PR text in the range. Route each candidate, grouped when several target one topic, through `domain-kb-ingest` in `fact` mode. A range that yields no candidate is a quiet Distil.

**Ingest (`import`).** Inline text or one file is one call in `fact` mode with `Hint` from the text's shape and `Imported from` `inline` for text, as below for a file. A directory is walked in path order for every `*.md` under it, excluding `tmp/`, `_templates/`, `_index/`, `repos/`, `devenv/`, dot-folders, `README.md`, `CLAUDE.md`, `index.md`, `ATLAS.md`, and any file with `generated: domain-sync`. Each remaining file is one call in `document` mode: the whole file is `Text`, its source folder is `Hint`, `Imported from` is the `--in` path as typed joined with the file's relative path, and the source is never copied or moved. `Split candidates` from every call are collected for the report; no curated document is split. After the last file, every relative link in the files written this run is checked: a target that never existed in the source is listed under `Dangling in source`, a target that was placed at another path under `Broken by move` with its new path; links are not rewritten, since only `domain-kb-ingest` writes curated files.

### Step 9 - Rank (`init`, `update`)

Per the layout's Rank pass and tiers: `_index/priority.json` rewritten whole with `priority` and `ranked_by` for every card Step 13 keeps; no card is written, except that a card still carrying either key in its frontmatter, an orphan included, has both lines removed (a `mark`). `most changed` counts the distinct commits over the card's in-scope `files` whose committer date (`%cs`) falls in the window. In-degree counts the cards in the card set naming the flow under `## Related`, a `flow to trace:` entry whose surface matches the card's Trigger Surface under the layout's Surfaces-match-whole rule included.

### Step 10 - Analyse (`init`, `update`)

- Use skill: `domain-rationale-chain` once over the Rules rows of every card in the card set (the rows of a card outside the card set leave the ledger, register, playbook, and contracts here; a row an earlier Link pass added is carried with its id until Step 11 replaces it); each `R-new` row takes the next number after the highest id in the previous ledger, its non-code and carried rows included, before `ledger/rules.md`, `ledger/unknown-rationale.md`, and `ledger/chains.md` are written; then mark each card's Rules row. Pasted Notes for a rule are appended to the ledger here.
- Use skill: `domain-behavioral-analysis` over every repo with its scope, the Window, the reverse index, and every card's Monitors line with its `ranked_by` from `_index/priority.json`; write `debt/recent-risk.md` from its Recent risk table and convert its hotspot, single-point, and coupling rows per its Register rows recipe.
- `debt/register.md` takes every card-set Debt row, with `Fix` as the change that removes the finding and `Detection` as the existing monitor, capture, or review gate that would catch it (`none` when there is none), and every converted analysis row with the `Fix` and `Detection` its Register rows recipe gives; rows with the same class and `Location` file (line number ignored) across cards merge into one row listing every flow; ids `D-<n>` are kept where a prior row has the same `Location` file (line number ignored; the whole `Location` string for a module or `A with B` row) and the same `Signal` class, and assigned after the highest otherwise. `debt/detection-gaps.md` classifies every card in the card set by its Monitors and Error tracker lines and rows the `no signal` and `capture only` flows by their `_index/priority.json` priority, with the class in `Signal` and what is missing in `Gap` (`no monitor` for a `capture only` flow, `no monitor and no capture` for a `no signal` flow).
- `playbook/by-symptom.md` takes one row per distinct `User sees` across the cards' Failure modes, with its flows and first checks; `Past incidents` is filled in Step 11.
- `contracts/<caller>.md` takes one file per caller: every repo one of whose card-set cards' hop lists crosses into another repo's `internal api` surface is a caller of that surface, and every `(external - from traces)` caller in a card's Contract is a caller of its surface; each file lists the surfaces used and the sharp edges the cards' Rules and Edge branches record on them, with `Doc` left `none - no consumer doc` for Step 11 and `Kind` `ui app` for a repo whose `Stack Type` is `frontend`, `external system` for a traces-only caller, `team` otherwise. A caller file no card names any longer is marked `orphaned`; when no card names a caller, `contracts/` holds no file but orphaned ones and `Linked` counts 0 contracts.
- Regenerate every non-orphaned inventory with `Used by flows` filled from the card set: a row is used by every card whose Trigger Surface or hop list matches its surface under the layout's Surfaces-match-whole rule, and `none - no flow cites it` otherwise. Mark each card's `R-new` and `D-new` ids and Contract `Callers` from `contracts/`; resolve every `flow to trace: <kind>: <surface>` entry whose surface matches a card's Trigger Surface under that rule to `<capability>/<flow>`.

### Step 11 - Link (`init`, `update`; `import` on a synced root)

Read the curated layer once and point the generated layer at it, in this order, each a `mark`: (1) for every `rules/` doc, the ledger row whose `Enforced at` site the doc's `Where enforced` names (two rows at one site: each whose rule text the doc states), else whose rule text the doc states (a mention of the rule's subject is not a match), gets `Doc: <path>` in the ledger and in every card Rules row with that id; a doc no row matches (carried Link rows take no part in the match: on `import`, the non-`code` rows and the `code` rows whose id no card's Rules table holds) replaces its carried row, the one with the same `Doc` path, else the same rule text, keeping its id, else becomes a new ledger row numbered after the highest id (a carried row no doc replaces is removed), its `Rule` the first sentence of the doc's `## Statement`, its `Kind` the doc's `## Enforcement` `Kind:` value (absent: `code` when `Where enforced` is a `file:line`, else `process`), `Enforced at` the doc's `Where enforced` `file:line` for `code` and `process - <path>` otherwise, `Doc` the path, `Flows` from the card-set cards whose surfaces the doc names (`## Related` entries are filled later, at (5)), else the carried row's `Flows`, else `none - not tied to a flow`; Use skill: `domain-rationale-chain` for each new or replaced row; its block fills the row's `Rationale`, `Confidence`, `Quirk`, and `Last touched`, replaces the `## R-n` block of the same id in `ledger/chains.md`, else is appended (the file created from this run's blocks when absent), and an `unknown` row is copied to `unknown-rationale.md` (created likewise); (2) every register row whose `Location` a `tech-debt/` item names gets `Doc: tech-debt/<file>.md#<anchor>`; (3) every `contracts/<caller>.md` gets `Doc: consumers/<name>.md` when a doc of that name, or of a name the caller's aliases hold, exists; (4) every playbook row gets `Past incidents` from the `incidents/` files whose text names its symptom or a flow in the row; (5) every card-set card's `## Related` gets `doc: <path>` (an entry already present is not added twice) for each curated doc whose text names the card's Trigger Surface, an entity in its State changes, or a rule text in its Rules, and `consumer: consumers/<name>.md` for each external target or caller with a doc. External callers Step 6 named that have no `consumers/` doc are listed under `Consumers without a doc`. Nothing curated is written.

### Step 12 - Verify citations (`init`, `update`; `import` on a synced root)

Read-only. Run the layout's Verify citations pass against the tip this run records (`import`: the recorded `sha`), rewrite ATLAS `## Citation drift` whole from the result, and count it for the summary; no doc is edited.

### Step 13 - Finalise (`init`, `update`; `import` on a synced root)

On `init`, first delete every orphaned generated file whose `## Notes` is empty, a `capability.md` whose cards were all deleted with them; on `init` and `update`, delete the old file of every card Step 7 traced under a new capability (or Step 6 found already traced there) and a `capability.md` left with no card, each counted under `deleted`. Then regenerate `capability.md` for every capability with at least one card (pasted Notes for a capability appended here); `overview/domain-model.md` (actors from Triggers, entities from State changes, external systems from `(external - not in repos)` targets, value flow from the `moves money` flows); `overview/state-machines.md` from every State changes row grouped by entity; `overview/glossary.md` from entity, status, and capability names with the code identifiers the cards cite and the `Also called` aliases the curated docs use; `overview/not-supported.md` from rules and error branches that reject a business case outright; then `ATLAS.md` with the counts line, `### Untraced` (on a run resumed past Step 7, the due triggers per Step 7 with no card), and the carried tables; `CLAUDE.md` with its carried sections and `## Repos` holding the `sha` Step 14 records for each repo; and `index.md` with `## Files` from the generated files and `## Curated` from every curated doc's frontmatter. Remove a `.gitkeep` from every curated folder that now holds a Markdown file. On `import` only `index.md`, the `.gitkeep` removal, and the `CLAUDE.md` `## Repos` table run.

### Step 14 - Record

Write `sync-state.json` whole per the layout's Record pass (`sha` per repo at the tip this run used, a repo outside `--repos` and every repo on `import` keeping its recorded `sha`; `synced` today and `window` the run's, both kept on `import`; `fetch` `false` only under `--no-fetch` and `true` otherwise, a Fetch pass every repo skipped included, kept on `import`; `version` kept; `path`, `stack`, and `database` kept, written from Step 2 for a `new` repo; `branch` and `scope` from Step 2, kept on `import`; `surfaces` per repo from its inventory's real rows, `0` when absent; `curated` one key per layout key, `specs` counting both subfolders, zeros included; `in_progress` cleared); then run the layout's checks on every path this run read, counting `verified` and listing under `Drift` the failures this run's writes did not fix; then write the Output Format block to `_index/last-sync.md` and emit it, every value read from the files written or, when no file holds it, from the pass that produced it this run; on a resumed run every slot whose only source is a pass before `{pass}` reads its `unknown - resumed at {pass}` form, an `n/a` form winning and a slot a retyped flag settles (`Fetch` `disabled` under `--no-fetch`) written.

## Avoid

- Writing any file other than the `--resume` `import:*` clear before the preflight passes, or running a git write other than the Step 4 fetch, guarded bump, and submodule gitlink stage
- Advancing a repo's recorded `sha` before the Record pass, or on `import`
- Regenerating a card without carrying its `## Notes`, aliases, and ids
- Inventing a repository URL for the `Setup required` block
- Fetching runtime evidence before the card is traced, or from a tool the preflight found unreachable
- Writing, moving, or copying a curated file by any means other than a `domain-kb-ingest` call, or reading one into `## Notes`
